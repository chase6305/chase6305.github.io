## 复制与章节导航

剪贴板 Promise 尚未完成时，原来的原生 `disabled` 会在后续帧使复制按钮失去焦点。权限拒绝后，无条件的手动选择又会把已经离开的读者拉回代码块，覆盖其新选区。现在使用 `aria-disabled`、`aria-busy` 与重入保护保留焦点；只在文档仍活动、焦点和选区均未改变时自动选择代码。

短代码块的手动选择还会触发尺寸观察：原检查因代码不溢出移除 `tabindex`，使选中的 `pre` 失焦。现在保留正在使用的焦点，读者离开后再清理临时 Tab 入口。回归包含延迟成功、延迟拒绝、重复激活、选区变化、后台标签页、缺少 Clipboard API 和短代码块。

手机目录的延迟帧也能覆盖后续 Tab 焦点。现在关闭目录、更新原生片段地址、聚焦及滚动在同次激活中完成，保留 `hashchange` 和前进／后退；Ctrl、Meta、Shift、Alt 及辅助按键交给浏览器处理。36 组窄屏／主题／字号组合、五种修饰点击、旧式 span 锚点与历史导航通过；另通过全站 912 个章节／图注组合，其中 536 个是图注。

## 焦点与高对比度阅读

主页、博客、归档、标签和项目卡片原来使用 35% 不透明度的焦点框，126 个采样组合低于 3:1。改为实色主题强调色后，540 个普通及强制颜色组合通过，最小实测比值约为 4.94。这里检查仓库维护的 outline 样式，不把文章底部原有的边框焦点样式误报为缺失。

阈值参考 [W3C 对非文本状态提示的说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。这些数值是 Chrome 对均匀背景的绘制颜色诊断；不代表整站已完成正式的 WCAG 认证，带渐变或图片的背景仍需目视检查。

滤波实验中的 Canvas 不会自动接受浏览器的强制颜色映射：浅色系统背景上仍画浅色文字，坐标对比度曾降至 1.45；反向配色约为 2.96。现在读取系统实际前景色，并以细点线、虚线和粗实线区分测量、真值和输出。普通模式也增强测量曲线可见度；选中的观察区间在强制颜色下保留加粗与下划线。

切换强制颜色或系统明暗偏好会直接重画，无需改参数或窗口尺寸。270 组算法／视图／主题／宽度／配色组合通过，数值指标一致。额外检查发现深色强制颜色会覆盖白纸打印背景，现仅在打印媒体中保留原有中性配色；普通与强制颜色打印各 564 组检查通过，包含无 JavaScript、公式、表格、代码与折叠内容恢复。
