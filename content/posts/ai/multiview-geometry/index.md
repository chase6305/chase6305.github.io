假设机器人在同一时刻保存了左胸、右胸和腕部三张图片。我们想知道：它们是否看到了同一个桌角？三台相机在哪里？桌面离相机多远？整段操作中相机又是怎样运动的？

这些问题相互关联，却需要不同的输出。**RoMaV2 主要回答像素之间怎样对应；VGGT 和 Depth Anything 3（DA3）都能从图像恢复相机与三维几何。** 后两者的能力有很大重叠，不能把它们理解成“一个做三维，一个只做深度”。[RoMaV2 官方实现](https://github.com/Parskatt/RoMaV2)、[VGGT 官方实现](https://github.com/facebookresearch/vggt)、[DA3 官方实现](https://github.com/ByteDance-Seed/Depth-Anything-3)

本文围绕 dpv2 这类多相机数据处理需求，梳理匹配、重建、深度、定位和跟踪的开源方案。项目能力与接口依据 **2026-10-17 核对的官方资料**；后文的接入顺序是针对这一场景的工程建议，效果需要在自己的留出样本上比较。

## 1. 先区分输出：对应、深度、点图与位姿 {#outputs}

| 技术 | 核心输出 | 适合回答的问题 |
| --- | --- | --- |
| [RoMaV2](https://github.com/Parskatt/RoMaV2) | 图像对的稠密对应及相关置信信息 | 哪些像素可能是同一个物理点？ |
| [LightGlue](https://github.com/cvg/LightGlue) | 已提取关键点之间的匹配 | 用稀疏对应估计几何，能否得到另一组证据？ |
| [DA3](https://github.com/ByteDance-Seed/Depth-Anything-3) | 按模型版本提供深度、相机参数等 | 能否联合恢复多视图几何，或利用已有位姿估计深度？ |
| [VGGT](https://github.com/facebookresearch/vggt) | 相机参数、深度、三维点图、查询点的跨视图跟踪 | 能否一次前向推理联合估计场景与相机？ |
| [DUSt3R / MASt3R](https://github.com/naver/mast3r) | 图像对的三维点图；MASt3R 还提供局部描述子 | 如何把图像匹配与三维预测联系起来？ |
| [MapAnything](https://github.com/facebookresearch/map-anything) | 米制几何、相机参数等 | 已有内参、位姿或部分深度怎样参与重建？ |
| [MoGe](https://github.com/microsoft/MoGe) / [UniDepthV2](https://github.com/lpiccinelli-eth/UniDepth) | 单图深度、三维点及相关相机信息，依版本而定 | 单路相机缺少公共视野时，还能估计什么？ |
| [FoundationStereo](https://github.com/NVlabs/FoundationStereo) | 校正后双目图像的稠密视差 | 如何利用已知双目基线恢复深度？ |
| [COLMAP](https://github.com/colmap/colmap) / [hloc](https://github.com/cvg/Hierarchical-Localization) | 重建或定位流程中的相机位姿、三维点 | 能否用匹配、三角化与优化建立几何基线？ |
| [DROID-SLAM](https://github.com/princeton-vl/DROID-SLAM) / [MASt3R-SLAM](https://github.com/rmurai0610/MASt3R-SLAM) | 视频中的相机轨迹与地图 | 相机随时间怎样运动，地图是否漂移？ |
| [CoTracker3](https://github.com/facebookresearch/co-tracker) | 视频点的二维轨迹与可见性 | 某个桌角或物体点后来去了哪里？ |
{.table-readable}

几个词需要单独说明：

**像素对应**是一对二维坐标，例如左图的 $(u_L,v_L)$ 与右图的 $(u_R,v_R)$。它描述图像证据，还没有直接给出该点离相机多远。

**深度图**为每个像素赋一个深度。先确认它表示相机光轴方向的 $Z$，还是沿观察射线的距离，以及数值是否有米制意义。**三维点图（point map）**则直接为每个像素给出一个 $(x,y,z)$；只有核对了坐标系，这些点才能正确叠加。[VGGT 的点图与反投影接口](https://github.com/facebookresearch/vggt#detailed-usage)

**相机位姿**描述相机坐标系与参考坐标系的关系；**点轨迹**描述指定点跨图像的位置。VGGT 跟踪接口返回查询点的跨视图位置及可见性等信息，不能把这些二维位置直接当成物体在世界系中的米制运动。[VGGT 跟踪分支示例](https://github.com/facebookresearch/vggt#detailed-usage)

## 2. RoMaV2 与 LightGlue：先找出同一个点 {#matching}

### 2.1 稠密匹配与稀疏匹配怎样分工

RoMaV2 处理一对图像，估计稠密对应，再采样匹配用于几何估计。官方接口还涉及归一化坐标到像素坐标的转换，不能把输出的 $[-1,1]$ 坐标直接交给使用像素单位的几何函数。[RoMaV2 使用示例](https://github.com/Parskatt/RoMaV2#how-to-use)

LightGlue 是关键点匹配器，通常先用 SuperPoint、DISK、ALIKED 或 SIFT 等提取位置与描述子，再建立稀疏对应。它适合充当另一种匹配前端；“匹配更少”不等于“信息更少”，分布均匀且可靠的匹配往往比集中在一小块区域的密集点更有用。[LightGlue 官方示例与配置](https://github.com/cvg/LightGlue#installation-and-demo)

对三台相机，可以分别运行左胸—右胸、左胸—腕部、右胸—腕部。每一对都可能有不同的公共视野和遮挡，三张图不保证每个点都同时可见。把两组对应连成三视图轨迹时，还要检查它们是否真的指向同一个物理点；例如检查左胸→右胸→腕部→左胸的循环是否回到原位置附近。

还应检查视图之间是否连通：左胸能匹配右胸、右胸能匹配腕部时，可以通过共同视图把几何约束连接起来，不要求每一对都直接重叠。但若腕部与另外两路完全没有可关联的静态区域，仅把三张图送入网络，不能证明三者的相对位置已得到图像约束；需要已知外参、跨时刻的连接视图或其他观测补上这条联系。

连通也不保证所有几何量都可恢复。仅有两对本质矩阵时，每条边的平移仍只有方向，边与边之间的相对长度不一定确定；还需要足够的跨视图三维点关联、已知基线或其他约束。多视图优化可以综合已有证据，不能自动补齐缺失的尺度信息。

### 2.2 匹配之后还需要几何方法

有了对应点，可以结合内参估计本质矩阵与相对位姿，也可以在已知相机参数时三角化。RANSAC 等鲁棒估计用于剔除不符合几何模型的对应，但不会自动补上缺失的信息：普通两视图本质矩阵恢复的平移只有方向，绝对长度仍需要基线、测距或其他尺度约束；纯旋转、很小的视差以及近似平面场景，也会使部分几何估计不稳定。[OpenCV 标定与三维重建接口](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)

因此，用 RoMaV2 检查标定时，更准确的说法是：**匹配提供候选对应，标定参数和几何残差共同决定这些对应是否支持当前标定。** 匹配结果自身也可能错误，不能充当无条件真值。

## 3. VGGT、DA3 与其他联合重建方案 {#reconstruction}

### 3.1 VGGT：多视图聚合与多个预测分支

VGGT 可以输入同一场景的多张图片，聚合视图信息，再通过相机、深度、点图和跟踪等分支输出几何量。对三相机例子，它能联合估计相机参数与桌面结构。[VGGT 论文](https://arxiv.org/abs/2503.11651)

联合估计的关键是**视图之间会交换特征信息**。图像先转换成 patch token；聚合器交替进行图内 attention 和跨全部视图的 attention：前者组织每张图自身的外观与空间关系，后者让不同相机中的特征互相参考。同一个桌角在左胸和腕部图片中的证据，因此可以共同影响预测。[VGGT 聚合器实现](https://github.com/facebookresearch/vggt/blob/a288dd0f14786c93483e45524328726ab7b1b4ce/vggt/models/aggregator.py)

这些关联由网络学习形成。是否真的支持当前相机几何，还需要检查重叠、遮挡与重投影；attention 权重本身不能直接当作经过几何验证的像素匹配。

三维点有两条获得路径：直接使用点图分支，或把预测深度与相机参数反投影。官方详细示例指出，后一条路径通常能得到更准确的三维点；对照实验应记录使用了哪一种，不能把同一模型的两条路径混成一个结果。[VGGT 架构与详细使用](https://github.com/facebookresearch/vggt#detailed-usage)

跟踪分支还有独立的查询输入：当前实现只有在提供 `query_points` 时才调用它。普通的图像推理结果不一定包含轨迹；需要明确查询点属于哪个处理后的图像网格，并将返回的二维位置与三维点图区分开。[VGGT 前向推理与查询点条件](https://github.com/facebookresearch/vggt/blob/a288dd0f14786c93483e45524328726ab7b1b4ce/vggt/models/vggt.py)

一次前向推理描述的是基础预测过程。导出 COLMAP 的示例还可以选择 bundle adjustment（BA，束调整），进一步优化相机与三维点；比较速度或误差时，要说明是否启用了这一步。[VGGT 的 COLMAP 导出与 BA](https://github.com/facebookresearch/vggt#exporting-to-colmap-format)

### 3.2 DA3：深度与射线表示，以及不同的模型系列

DA3 以深度与射线表示组织几何预测，支持未知位姿的重建，也支持输入相机参数的条件化推理。其代码仍有具体的预测与解码路径；“统一表示”不意味着实现里只有一个输出张量。[DA3 论文](https://arxiv.org/abs/2511.10647)

这套表示怎样恢复三维点？对像素 $\tilde p=(u,v,1)^\mathsf T$，设相机中心为 $C_w$，$R_{wc}$ 将相机方向旋转到世界系，深度为 $z$，则射线方向与三维点可以写成：

$$
d_w=R_{wc}K^{-1}\tilde p.
$$

$$
X_w=C_w+z\,d_w.
$$

DA3 论文中的射线图为每个像素保存三维起点和三维方向，共六个分量；**方向没有归一化**，因此不能把这里的 $z$ 直接当作沿单位射线的距离。深度与射线配合，就能组织点图和相机几何。对理想针孔相机，同一幅图的射线起点应共享相机中心；逐像素预测还需要归并或拟合，才能得到相机参数。[论文的 depth-ray 定义](https://arxiv.org/html/2511.10647v1#S3.SS1)

选择权重时，应区分以下能力：

| DA3 系列 | 主要定位 | 比较时需要记录 |
| --- | --- | --- |
| Main / Any-view | 单目或多视图几何、相机估计与位姿条件化 | 模型大小、权重版本、相机解码路径 |
| Mono | 单目相对深度 | 不把相对数值直接当米 |
| Metric | 单目米制深度 | 焦距约定与输出尺度换算 |
| Nested | 组合 Any-view 与米制深度模型 | 几何预测与尺度估计来自哪些组件 |
{.table-readable}

具体特性以模型卡为准，不能把某个版本的功能推广到整个系列。当前模型卡还区分带 `-1.1` 后缀的更新权重；旧实验应保存原权重标识，新实验应记录实际选用版本。`DA3METRIC-LARGE` 的官方换算涉及像素焦距，Nested 的接口输出则已有米制尺度。[DA3 模型卡与尺度说明](https://github.com/ByteDance-Seed/Depth-Anything-3#-model-cards)

一个特别影响标定评估的细节是：DA3 的 `align_to_input_ext_scale=True` 在提供外参时，会将输出外参替换为输入外参，并缩放深度。因此，不能拿这种输出与输入外参一致，来证明模型独立验证了标定。要检查自主位姿预测，应另外保留不提供位姿的运行。[DA3 位姿条件化与对齐参数](https://github.com/ByteDance-Seed/Depth-Anything-3/blob/3d835ec1a5802d64a8b8b15f817a1ab54809bfe4/docs/API.md)

仅改成 `align_to_input_ext_scale=False` 也不等于恢复了自主预测：输入位姿仍已参与网络推理，返回的位姿还经过对输入位姿的对齐。当前 API 默认 `use_ray_pose=False`，使用相机解码路径；启用它才选择射线解码位姿。这两个开关分别控制后处理与位姿解码，应分开记录。[DA3 的推理与对齐实现](https://github.com/ByteDance-Seed/Depth-Anything-3/blob/3d835ec1a5802d64a8b8b15f817a1ab54809bfe4/src/depth_anything_3/api.py)

还应区分内部表示与接口返回值：当前网络在解析相机参数后会移除中间的 `ray` 与 `ray_conf` 字段，不能假设高层 `prediction` 保留了射线图。构造点云时，通常可以使用接口给出的深度、内参与外参反投影。[DA3 相机解码与字段处理](https://github.com/ByteDance-Seed/Depth-Anything-3/blob/3d835ec1a5802d64a8b8b15f817a1ab54809bfe4/src/depth_anything_3/model/da3.py)

### 3.3 DUSt3R 与 MASt3R：连接点图和匹配

[DUSt3R](https://github.com/naver/dust3r) 从图像对预测三维点图；多图流程可以把成对结果放入全局对齐。它展示了一条直接预测三维几何的路线，而不是把所有几何都留给传统匹配后端。

[MASt3R](https://arxiv.org/abs/2406.09756) 在这一路线上加入局部特征描述子，使匹配与三维预测联系得更紧。适合研究“换一组对应，几何是否仍成立”。其[仓库](https://github.com/naver/mast3r)中的 MASt3R-SfM 流程与后文的 MASt3R-SLAM 是不同系统，前者侧重图像集合的重建，后者侧重连续视频的定位与建图。

### 3.4 MapAnything：让已有几何信息参与推理

MapAnything 能利用图像与可选的标定、位姿、深度等输入，预测场景的米制几何。它适合已有部分相机信息的采集系统，也适合比较“只给图片”与“提供几何先验”两种条件。[MapAnything 官方概述](https://github.com/facebookresearch/map-anything)

“灵活输入”仍有接口约束：常用 `infer` 接口接收 `depth_z` 时还需要内参或射线方向；如果某个视图带位姿，参考视图也必须有位姿；`camera_poses` 使用 OpenCV 轴约定下的 **cam2world**。这些要求应在适配器中显式检查。[MapAnything 多模态输入要求](https://github.com/facebookresearch/map-anything/blob/3d10cf7a3016fc0f9bb13a071ee66c47b10be0d9/README.md#multi-modal-inference)

对比 DA3 与 MapAnything 时，可以设置“都不给位姿”以及“都给同一组标定”两组实验。后一组衡量如何利用已有信息，前一组才适合观察独立预测与现有标定之间的差异。

## 4. 单目与双目深度：尺度从哪里来 {#depth}

### 4.1 MoGe 与 UniDepthV2：公共视野之外的单图估计

腕部相机可能主要看向手和物体，与胸部相机没有足够重叠。这时无法仅靠当前时刻的双目对应恢复该区域，单目模型可以利用学习到的场景规律估计几何。

[MoGe](https://github.com/microsoft/MoGe) 从单图估计三维几何。MoGe-1 与后续米制版本需要区分：MoGe-2 提供米制点图与深度，部分权重还提供法线；核对时官方仓库也已列出 MoGe-3，实验应固定具体版本与权重，而不只写“MoGe”。

[UniDepthV2](https://github.com/lpiccinelli-eth/UniDepth) 面向单目米制深度，也可以输入已有相机参数；V2 接口提供具体相机模型类，因此应按真实成像模型准备输入。已知内参能减少部分不确定性，但不能从单张图中凭空获得另一台相机的观测证据。

**米制输出与实测距离需要区分。** 单目模型的尺度依赖训练形成的先验和输入约定，陌生物体、裁剪、反射、透明表面或特殊镜头都可能带来误差。可以将它作为单路参考，再用已知尺寸、深度传感器或可靠双目重叠区检查尺度。

### 4.2 FoundationStereo：利用已知双目基线

FoundationStereo 输入双目图片，输出稠密视差。官方要求输入已经去畸变并完成立体校正，极线水平，左右顺序正确。它不替代内外参标定，也不能把任意两张未校正的相机图片直接当作标准左右目输入。[FoundationStereo 输入要求](https://github.com/NVlabs/FoundationStereo)

在校正后两相机焦距一致、水平主点对齐的理想针孔模型中，设视差 $d=u_L-u_R$，焦距为 $f_x$，基线长度为 $B$，则：

$$
Z=\frac{f_xB}{d}.
$$

这里 $f_x$ 和 $d$ 都用像素，$B$ 用米，得到的 $Z$ 是米。若校正后的水平主点不同，要使用修正后的视差，或按校正得到的投影矩阵、$Q$ 矩阵反投影，不能无条件套用上式。[OpenCV 立体校正与视差反投影](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)

举一组**构造数值**：$f_x=800\ \mathrm{px}$、$B=0.12\ \mathrm{m}$、$d=48\ \mathrm{px}$，得到 $Z=2\ \mathrm{m}$。若视差误估成 $47\ \mathrm{px}$，深度变成约 $2.043\ \mathrm{m}$；当视差只有 $12\ \mathrm{px}$ 时，同样少估一个像素，会把 $8\ \mathrm{m}$ 估成约 $8.727\ \mathrm{m}$。远处的小视差会放大误差。

这条路线的尺度来自已知基线，因而很适合与 DA3、VGGT 的深度对照。但它仍共享标定、同步与遮挡等误差源：如果基线或内参错了，多种双目算法也可能一起给出错误的米制结果。

立体校正还可能旋转相机的坐标轴，因此校正图中的 $Z$ 深度与原相机的 $Z$ 深度不一定相同。比较前，应在校正相机系反投影，使用校正旋转的逆变换回原相机系，再投影到公共参考网格，并检查遮挡与投影冲突；只对深度图套用 RGB 的重采样映射，不足以保证深度定义一致。[OpenCV 校正旋转与视差反投影坐标系](https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html)

## 5. COLMAP、hloc、SLAM 与 CoTracker3 {#temporal}

### 5.1 图像集合重建与已有地图定位

[COLMAP](https://github.com/colmap/colmap) 提供 SfM（运动恢复结构）与 MVS（多视图立体）流程，通过图像关联、几何估计、三角化和优化恢复相机及场景。它适合作为与前馈网络不同的几何基线；无外部尺度约束的普通单目图像重建同样存在尺度自由度。

[hloc](https://github.com/cvg/Hierarchical-Localization) 把检索、局部特征、匹配、三角化与定位组织成流程，支持 LightGlue 等前端。如果已有场景地图，问题可以从“重新恢复整个场景”变成“把当前图片定位到地图中”。三角化路径也能利用已有相机位姿；评估时需记录哪些参数被固定、哪些允许优化。

对只有三张、近似平面的桌面图片，传统 SfM 未必有足够约束。可以另取机器人移动期间的背景图像建立离线地图，再使用保留帧测试定位；不要把同一批建图帧的拟合残差当成独立定位精度。

### 5.2 视频 SLAM：恢复相机随时间的运动

[DROID-SLAM](https://github.com/princeton-vl/DROID-SLAM) 面向单目、双目或 RGB-D 视频，联合估计相机运动与稠密几何。[MASt3R-SLAM](https://github.com/rmurai0610/MASt3R-SLAM) 使用 MASt3R 的重建与匹配先验构建单目稠密 SLAM，并研究已知与未知标定条件。[MASt3R-SLAM 论文](https://arxiv.org/abs/2412.12392)

它们补上的是时间维度：相邻帧之间怎样连接，轨迹是否漂移，地图是否保持一致。把三台相机同一时刻的图像按顺序拼起来，不会自然变成满足单相机视频假设的输入。多路融合需要相应系统支持，腕部相机与胸部相机之间随关节变化的变换也不能当成恒定外参。

### 5.3 CoTracker3：跟踪点的位置与可见性

CoTracker3 输出视频中点的二维轨迹与可见性，可以跟踪桌角、手指附近或物体表面的点。官方示例的轨迹末维是两个图像坐标分量；可见性用于判断哪些时刻的轨迹适合继续分析。[CoTracker3 输入输出](https://github.com/facebookresearch/co-tracker#quick-start)

如果相机移动，即使桌角在世界中静止，它在图像里也会移动。要恢复世界系运动，还需要深度、相机位姿，或同步多视图与三角化等额外信息。CoTracker3 可以补充时间上的关联，不能单独替代三维重建或 SLAM。

## 6. 比较之前，先统一坐标、图像尺寸与尺度 {#coordinates}

### 6.1 明确变换方向和深度定义

本文统一用 $T_{cw}$ 表示 world2cam，即：

$$
X_c=R_{cw}X_w+t_{cw}.
$$

对已去畸变的针孔图像，若深度 $z$ 表示光轴方向的 $Z$，像素齐次坐标为 $\tilde p=(u,v,1)^\mathsf{T}$，则：

$$
X_c=zK^{-1}\tilde p.
$$

$$
X_w=R_{cw}^{\mathsf T}(X_c-t_{cw}).
$$

这里 $K$ 是与该深度图像素网格一致的内参；若输入是沿单位射线的距离，则应先归一化射线，再乘距离。畸变图像和鱼眼模型还需要对应的反投影方法。

VGGT 示例与 DA3 输出采用 OpenCV 风格的 world2cam；MapAnything 的 `camera_poses` 输入采用 cam2world。交换这两类矩阵时需要求逆。相机中心也不是 world2cam 的平移列，而是 $C_w=-R_{cw}^{\mathsf T}t_{cw}$。[VGGT 坐标约定](https://github.com/facebookresearch/vggt#detailed-usage)、[DA3 输出说明](https://github.com/ByteDance-Seed/Depth-Anything-3/blob/3d835ec1a5802d64a8b8b15f817a1ab54809bfe4/docs/API.md)、[MapAnything 位姿输入约定](https://github.com/facebookresearch/map-anything/blob/3d10cf7a3016fc0f9bb13a071ee66c47b10be0d9/README.md#multi-modal-inference)

### 6.2 裁剪和缩放必须同步更新内参

假设原图先从 $(x_0,y_0)$ 裁剪，再分别按 $s_x,s_y$ 缩放；在相应的连续像素坐标约定下：

$$
K'=AK.
$$

$$
A=\begin{bmatrix}
s_x&0&-s_xx_0\\
0&s_y&-s_yy_0\\
0&0&1
\end{bmatrix}.
$$

实际适配时，还要保存 padding 和库所用的像素中心约定。有些预处理会产生半像素偏移，应以真实坐标映射为准。原图上的 RoMa 匹配，不能直接与模型缩放裁剪后的深度、内参混用。

### 6.3 区分用于对齐的信息和用于验收的信息

相机与点云可能相差一个整体旋转、平移和尺度。对没有可靠米制尺度的重建，可以在同一场景范围拟合相似变换：

$$
X_{\mathrm{ref}}\approx sRX_{\mathrm{pred}}+t.
$$

同时记录拟合出的 $s$ 和对齐后的残差。若模型宣称输出米制尺度，应另外报告未经尺度修正的距离或尺度误差；只报告允许自由缩放后的点云误差，会掩盖米制尺度问题。

三台相机中心可能近似共线，仅靠它们拟合整体对齐会缺乏约束。可以利用分布更充分的静态三维点或独立测量，并把拟合对齐使用的数据与验收数据分开。对完整视频还应固定对齐的作用范围：逐帧重新拟合尺度可能把尺度漂移隐藏掉。

### 6.4 无需 GPU 的数值实验：零残差能说明什么 {#numerical-lab}

可以先打开[重投影与尺度交互实验](/labs/multiview-geometry/)，依次选择“外参方向用反”“缩放沿用旧内参”和“基线和深度都翻倍”。页面分别显示真实观测、候选匹配与重建投影，并保留未经尺度对齐的基线和深度倍数。

下载 [geometry_sanity.py](geometry_sanity.py)，在下载目录执行：

```bash
python3 -B \
  geometry_sanity.py
```

脚本仅使用 Python 标准库，运行后输出 JSON，并检查手算坐标及故意引入的错误。它使用**构造的针孔相机与静态三维点**，没有调用视觉模型；下面的结果用于验证几何约定，不是模型性能测试。

设左右相机朝向相同，右相机中心位于左相机右侧 $0.12\ \mathrm m$。两者 $f_x=f_y=800\ \mathrm{px}$，主点为 $(320,240)$；以左相机为世界系，桌角位于 $(0.2,0.1,2)\ \mathrm m$。投影得到左像素 $(400,280)$、右像素 $(352,280)$，视差为 $48\ \mathrm{px}$。右相机的 world2cam 平移为 $(-0.12,0,0)$：它将世界中的点减去相机中心。

| 构造条件 | 重投影误差 / px |
| --- | ---: |
| 正确的深度与外参 | 0 |
| 把右相机的 cam2world 当作 world2cam | 96 |
| 两图同样裁剪、缩小，并更新内参 | 0 |
| 两图同样裁剪、缩小，仍用旧内参 | 24 |
| 深度和基线同时扩大两倍 | 0 |
| 只把基线扩大两倍 | 48 |
{.table-readable}

这里的裁剪从 $(80,40)$ 开始，再将两个方向都缩小一半；更新后的焦距是 $400\ \mathrm{px}$，主点是 $(120,100)$。前两行使用原图网格，裁剪两行使用处理后的网格，分别与各自网格中的观测比较，不能直接用不同分辨率下的像素误差给方法排名。

最值得注意的是“深度和基线同时扩大两倍”：比例 $B/Z$ 不变，投影也不变，但恢复出的所有长度都错了一倍。**低重投影残差检查的是几何与图像是否相容，独立的米制尺度仍需另外验收。** 脚本还构造了沿同一水平极线错开 $100\ \mathrm{px}$ 的对应：纵向残差仍为零，使用正确深度重投影后却相差 $100\ \mathrm{px}$。这也解释了为什么极线误差和重投影误差需要同时看。

交互页可下载当前输入与结果为 `geometry-case.json`。把它和 Python 脚本放在同一目录，执行下列命令；Python 会从输入重新反投影、变换并投影，不使用 JSON 中已保存的结果：

```bash
python3 -B geometry_sanity.py \
  --input geometry-case.json
```

“沿极线错配 100 px”预设只移动候选匹配，真实观测保持不变，因此页面同时报告投影相对真实观测、相对候选匹配的两种误差。这里的真实观测来自已知的构造相机与三维点；真实数据中的匹配仍需独立核验。

还可以在原图网格下选择“外参方向用反”，再把匹配水平偏差设为 $96\ \mathrm{px}$，其余参数保持默认。错误的投影与错误的匹配会恰好重合：相对候选匹配的误差是零，相对真实观测仍相差 $96\ \mathrm{px}$。这说明错误参数与错误对应也可能相互支持，不能仅凭某一组匹配上的低残差就确认标定正确。

## 7. 面向三相机数据，怎样设计有用的对照 {#evaluation}

### 7.1 先固定输入条件

取一小批覆盖不同失败条件的片段，包括有纹理桌面、弱纹理、反光、遮挡、低重叠和快速运动。按整段采集或场景划分调参与留出数据，避免同一场景的近邻帧同时承担两种职责。

每个样本保存原图和时间戳、去畸变与裁剪记录、内参、相机变换及其单位、模型权重、推理配置和失败状态。胸口双目若刚性安装，其相对变换可以固定；腕部相机的变换通常要结合手眼标定、关节状态和时间同步得到。同步误差可能表现成几何残差，尤其在手和物体快速运动时。

### 7.2 按信息条件建立实验组

| 实验组 | 运行方式 | 能检查什么 |
| --- | --- | --- |
| 匹配前端 | RoMaV2 与特征提取器＋LightGlue，处理相同图像对 | 对应分布、几何内点、循环一致性及失败率 |
| 自主重建 | VGGT、DA3、MapAnything 只输入同一组 RGB | 独立预测的相对位姿、深度及重投影是否一致 |
| 已知几何条件 | DA3、MapAnything 输入同一组内外参 | 在相同先验下恢复的深度与图像证据是否一致 |
| 标定双目 | 对胸口双目校正，再运行 FoundationStereo | 已知基线下的深度，与其他方法在重叠区是否相符 |
| 单路参考 | MoGe 或 UniDepthV2，明确是否输入内参 | 无公共视野区的深度、尺度及跨帧变化 |
| 时间参考 | 合适的视频输入运行 SLAM；CoTracker3 另做二维跟踪 | 轨迹漂移、关联中断及动态区域问题 |
{.table-readable}

以上是实验设计，不代表这些方案已在 dpv2 上跑出效果。每增加一个模型，应先确认它为哪个问题提供额外证据，再决定是否值得完整接入。

比较时可以给每组结果附上“使用了哪些输入”的记录：图像、内参、位姿、深度、外部尺度与后端优化。这样即使两条路径使用同一个模型，也能区分它们回答的是自主恢复问题，还是利用已知几何补全深度的问题。

### 7.3 用匹配支持重建，也检查匹配自身

检查已有标定时，先把对应转换到与标定内参一致的去畸变像素网格，再用该标定推导出的基础矩阵 $F_{\mathrm{calib}}$ 检查极线约束；完成立体校正的双目还可统计 $|v_L-v_R|$。另开一组实验，允许 RANSAC 从对应中重新估计 $F$，用于检查这些对应能否支持某个两视图几何。**重新拟合后的低残差与原标定相容性是不同指标**，错误的原标定不会自动反映在新拟合的 $F$ 上。[OpenCV 极线几何](https://docs.opencv.org/4.x/da/de9/tutorial_py_epipolar_geometry.html)

残差定义也要明确：可使用归一化的点到极线距离，或注明所用的 Sampson 距离定义与是否取平方根。基础矩阵可以任意整体缩放，未归一化的代数残差数值不能直接当作像素误差。若对应已变成归一化相机坐标，应使用本质矩阵及相应阈值，不能混用像素单位的阈值。

极线约束本身也存在盲区：它约束对应点落在哪条线上，不能单独确定线上的正确位置，也不能恢复基线的米制长度。校正图上的纵向残差小，可以支持校正质量检查；深度精度和尺度还要继续验证。

设两图匹配为 $p_i,p_j$，用视图 $i$ 的深度将 $p_i$ 反投影，再用相机间变换投到视图 $j$，得到 $\hat p_j$。重投影残差为：

$$
e_{\mathrm{reproj}}=\lVert\hat p_j-p_j\rVert_2.
$$

只在有效深度、正深度、投影落入图像且满足可见性条件的区域统计。遮挡区即使几何正确，也不一定在另一张图中有可见对应；动态手和物体应与静态背景分开处理。

位姿比较也应拆开：相对于独立参考，分别报告相对旋转的角误差、平移方向的角误差；有可靠米制尺度时，再报告基线长度或位置误差。普通两视图估计的平移不能直接按米相减。如果两路的 world2cam 变换分别是 $T_{iw}$ 与 $T_{jw}$，从相机 $i$ 到相机 $j$ 的变换为 $T_{ji}=T_{jw}T_{iw}^{-1}$，可以用它消除共同世界坐标系选择的影响。

若三对相对变换都从同一组全局位姿派生，它们的环乘会按代数关系相消，不能把这种闭合作为独立验证。应另看从图像对独立估计的几何，或像素、深度与重投影证据。近零平移或退化极线还可能让平移方向角、极线距离不稳定或未定义；这类样本应单独记录，不能填成零误差。

同时报告中位数、高分位残差、有效覆盖率、失败率与样本数。不要只保留各模型最容易的少量点再比较均值；模型间的置信度也不一定同尺度，不能假设相同的数值阈值代表同样可靠。

比较方法时保留两种统计口径：在同一组有效对应上比较残差，检查精度差异；再按预先固定的候选像素或对应总数，统计各方法的有效覆盖与失败。这样既能公平比较共同区域，也不会把某个方法丢掉的困难区域从报告中抹去。所有像素阈值还应注明评估分辨率，或先统一映射回原图网格。

三角化参考同样需要写明使用的位姿与尺度：如果使用已有标定，它检查的是匹配与这组标定是否相容；如果使用估计位姿，结果又依赖位姿估计。**模型之间一致，只能增加相容性的证据；模型之间不一致，应作为复核线索。** 判断哪一方错误，还需要独立测量、标定板、已知尺寸或其他传感器等额外信息。

### 7.4 建议的接入顺序

对已有 RoMaV2、DA3 这类处理环节的数据系统，可以先补齐可重复的评估，再按目标增加对照：

1. **比较匹配前端时，接入 LightGlue。** 在相同图像对上保留关键点、对应和鲁棒估计结果，观察几何结论是否依赖某一种匹配器。
2. **胸口双目可靠时，接入 FoundationStereo。** 利用已知基线建立有明确尺度来源的深度参考，并同步保留校正质量检查。
3. **比较自主重建时，加入 VGGT。** 分别运行 VGGT 与 DA3，固定输入，记录点图或深度反投影路径，再对齐比较。
4. **已有几何信息需要参与推理时，加入 MapAnything。** 与 DA3 做相同先验条件下的对比。
5. **确认存在单路盲区或时间问题后，再增加单目模型、SLAM 或点跟踪。** 它们补充不同证据，不必全部塞进每一帧的流程。

这个顺序来自任务分工，不是效果排名。算力紧张时，可先离线处理少量代表片段，记录图像数量、处理分辨率、耗时、峰值显存和预处理范围，再决定是否扩大规模。

## 8. 复现时保存哪些版本信息 {#reproducibility}

文中涉及默认分支与字段处理的源码引用固定到 VGGT `a288dd0f1478`、DA3 `3d835ec1a580` 和 MapAnything `3d10cf7a3016`，于 2026-10-19 复核。这些是代码提交，不是模型权重版本；权重 revision 仍需单独记录。

每次运行至少记录仓库提交、权重仓库与 revision、模型系列、预处理尺寸、输入相机顺序、是否提供内外参、尺度处理方式以及是否进行后端优化。尤其不要让权重或默认配置更新后，实验仍沿用旧名称。

公开代码与权重的使用条件也需要分别查看。例如 DUSt3R / MASt3R 的仓库列有非商用条件，DA3 不同权重使用的许可证不同，VGGT 官方区分了原始权重与允许商用的特定 checkpoint。复用时应保存实际权重对应的模型卡与许可证。[DUSt3R 许可](https://github.com/naver/dust3r#license)、[MASt3R 许可](https://github.com/naver/mast3r#license)、[DA3 模型卡](https://github.com/ByteDance-Seed/Depth-Anything-3#-model-cards)、[VGGT 许可说明](https://github.com/facebookresearch/vggt#license)

几何结果进入点云过滤、配准和网格处理后，可继续阅读[Open3D 点云与网格指南]({{< relref "/posts/open3d/introduction" >}})；需要补齐标定概念时，可回到[OpenCV 相机标定]({{< relref "/posts/calibration/opencv" >}})；想把场景重建放进更长的数据生产链，可参考[Video to Data]({{< relref "/posts/ai/video-to-data" >}})。

## 阅读自测与验收 {#self-check}

1. **RoMaV2 能否直接输出三台相机的米制位置？** 常用接口先提供图像对的对应，位姿、三角化与绝对尺度还需要几何处理及额外约束。
2. **VGGT 与 DA3 是“三维重建”和“仅深度”的关系吗？** 两者都能恢复相机与三维几何，区别需要结合建模方式、接口和具体版本来看。
3. **DA3 的条件化输出与输入外参完全一致，说明标定正确吗？** 不能；默认尺度对齐选项可以直接使用输入外参，应另做不提供位姿的对照。
4. **米制单目深度与已知基线双目深度的尺度来源相同吗？** 前者依赖模型先验和输入约定，后者依赖标定基线与视差，两者都可能有误差。
5. **把原图关键点、缩放后的深度和旧内参混用会怎样？** 像素网格不一致，会产生错误反投影和重投影残差。
6. **MapAnything 的 cam2world 能直接当作 DA3 的 world2cam 使用吗？** 需要求逆，并核对轴向、单位及参考坐标系。
7. **三角化结果可以无条件作为真值吗？** 不能；它还依赖匹配、位姿、基线、视差和场景可观测性。
8. **CoTracker3 中桌角发生像素移动，说明桌子在世界中运动吗？** 相机运动同样会产生图像位移，需要额外几何信息区分。
9. **一个方法残差更低但只保留很少像素，就一定更好吗？** 应同时比较覆盖率、失败率、样本选择与置信度策略。
10. **每帧独立缩放对齐后误差很小，能证明尺度稳定吗？** 不能；应固定对齐范围，并单独报告尺度变化与未经修正的米制误差。
11. **DA3 的射线方向是单位向量吗？** 论文的深度—射线表示保留未归一化方向，乘以深度后再加相机中心得到三维点。
12. **设成 `align_to_input_ext_scale=False` 就是无位姿条件推理吗？** 不是；提供的位姿仍参与推理，输出也仍经过对齐，独立对照应省略位姿输入。
13. **从匹配重新拟合的基础矩阵残差很低，就证明原标定正确吗？** 不能；必须单独用原标定推导的几何检查对应。
14. **深度和基线同时扩大两倍，重投影误差会随之扩大吗？** 透视投影中的比例不变，重投影可以保持不变，但米制尺度已经错误。
15. **三台相机必须每一对都有公共视野吗？** 可以通过共同视图连接约束，但完全断开的视图仍需要已知外参或其他观测提供联系。
16. **VGGT 的普通图像推理一定输出点轨迹吗？** 当前实现还需要提供查询点，才能运行跟踪分支；轨迹输出是图像中的二维位置。
17. **跨视图 attention 能直接证明某对像素匹配正确吗？** 它是网络交换特征的机制，匹配正确性仍需对应与几何残差等证据检查。
18. **DA3 内部预测射线图，高层结果就一定带有 `ray` 字段吗？** 当前网络解析相机后会移除中间射线字段，点云可以通过返回的深度与相机参数反投影构造。
19. **交互实验中候选匹配与真实观测是一回事吗？** 候选匹配可以被故意移动，真实观测由固定构造相机和三维点确定；两种重投影误差需要分别报告。
20. **匹配图连通，就一定能恢复所有相机间的尺度吗？** 两视图平移方向之间仍可能缺少相对长度约束，需要共同三维关联、已知基线或其他观测。
21. **同一组全局位姿派生出的相对变换环乘为单位阵，能验证标定吗？** 它们本来就会代数相消，仍需独立图像、对应或深度证据。
22. **校正后的 Z 深度能直接与原相机深度逐像素比较吗？** 校正可能旋转光轴，需要反投影、变换并投影到公共网格，同时处理遮挡和冲突。
