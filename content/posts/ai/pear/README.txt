PEAR article: bounded offline examples
====================================

Files
  pear_sanity.py          Constructed probability, coordinate and score algebra
  reference-output.json  Numerical reference generated by that script
  probe_pear_contracts.py Fixed-source protocol, recorded methods and row counts

All examples use only the Python standard library. They do not train or load a
model, start a simulator, contact an inference service or open a robot device.

Numerical examples
  python3 -B pear_sanity.py --check
  python3 -B pear_sanity.py

The group calculator uses independent Bernoulli trials at a fixed probability.
Its expected candidate counts are not PEAR's measured rollout counts. Retained
group success fractions are conditional sampling statistics, not evaluation
success rates. Group advantages use an explicitly chosen population standard
deviation and epsilon=0, not every detail of the training framework.

Wilson intervals illustrate an IID binomial assumption. The paper's fixed scenes
and repeated object trials do not establish that assumption or general robot
reliability. The score example shows zero expected centered scores while the
reward gradient still differs from an on-policy one; it is not a GRPO trainer.
The coordinate example is rigid arithmetic, without IK, collision or dynamics.

Fixed official source probe
  git clone https://github.com/mit-han-lab/pear.git
  git -C pear checkout 2a81b2eec95e6e6f19c3fc0a80a38aebb40a30e2
  python3 -B probe_pear_contracts.py --source pear --output contracts.json

The probe verifies the revision and nine source hashes before executing source.
It loads the pure standard-library protocol module without a package initializer,
and extracts only the specified parser classes and RoboDojo _goals method with
AST. It also extracts only the dataset's pure range parser, expands JSON row
products and reads the stage-3 script's literal repeat count without running it.
Fake tokenizer, model validation and pose recorders replace dependencies.
No source controller module, NumPy, torch, SDK or device driver is imported.

What it checks:
  - Complete parts/fields; finite numbers; booleans and unknown fields rejected.
  - Training selects the last JSON block and rejects an invalid last block,
    rather than falling back to an earlier valid one. This extractor alone
    allows trailing text; the deployment parser requires a final fenced action.
  - Deployment rejects duplicate fields and a thinking block in the final answer.
  - RoboDojo goals add changes to unrounded measured quantities.
  - Zero actions record holds; simulated grippers use change sign, not magnitude.
  - LIBERO has four suites with 500 task/initial-state rows each, total 2,000.
  - RoboDojo's pickup/align file has 163 plus 165 unique rows, total 328. Six
    repetitions in the released stage-3 recipe give nominal weights 2,000:1,968.
  - official_smoke has 52 unique one-seed settings, excluding pickup and align;
    it is not the paper's complete 54-setting, ten-episodes-per-setting run.

Rows specify task/initial-state products. Repeating a file changes its nominal
weight, not its number of unique initial states. These checks do not run the
dataset framework or measure actual candidate/retained task frequencies.

The probe records exception types rather than treating every rejection as the
same ValueError: the deployment parser raises OverflowError for a very large
integer. The real station's surrounding recovery and stop behavior is outside
this offline probe. Full Pydantic action constraints, coordinate conversion,
IK, motion execution and task success are also outside its scope.

Existing --output files are preserved and rejected. No bytecode is written next
to source files. Source mismatches fail before source execution or output saving.
Official source remains under its Apache-2.0 license; no official source files
are redistributed in this download.
