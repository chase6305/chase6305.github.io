RLHF、RLVR 与 RLCD 不应被理解成三种互斥的“优化器”。它们首先回答的是：模型生成一批候选回答后，谁或什么机制告诉训练系统哪一个更好？ RLHF 借人类偏好，RLVR 借可执行的真值检查，RLCD（本文主用的含义）借对比提示构造的合成偏好。拿到这个信号以后，才选择 PPO、GRPO、DPO 或其他更新方式。

这一区分很实用：数学题能自动核验，并不意味着人类对“解释是否清楚”的偏好也被表示了；收集到高质量偏好对，也不意味着可以跳过验证器对代码测试的硬约束。实际配方常把三者串联或混合。

1. 先定位：后训练到底在优化什么？

预训练让模型预测海量文本中的下一个 token；监督微调（SFT）用示范回答教它某类交互格式；后训练则从已有策略 πθ0\pi_{\theta_0}πθ0​​ 出发，反复生成回答 y∼πθ(⋅∣x)y\sim\pi_\theta(\cdot\mid x)y∼πθ​(⋅∣x)，依据某个评分 r(x,y)r(x,y)r(x,y) 改变其分布。一个常见的抽象目标是：

max⁡θ  Ex∼D, y∼πθ(⋅∣x)[r(x,y)]−β DKL(πθ∥πref). \max_\theta\;\mathbb E_{x\sim D,\,y\sim\pi_\theta(\cdot\mid x)}[r(x,y)] -\beta\,D_{\mathrm{KL}}(\pi_\theta\Vert\pi_{\mathrm{ref}}). θmax​Ex∼D,y∼πθ​(⋅∣x)​[r(x,y)]−βDKL​(πθ​∥πref​).

第一项偏向高分回答，第二项限制策略不要为追逐评分而偏离参考模型过远。这个式子不是所有实现的逐字公式：有的训练不加 KL，有的用 token 级近似，有的直接在离线偏好对上优化。它揭示的共同点是：优化器只会放大评分函数所奖励的东西。 因此路线选择的核心不是先问“用 PPO 还是 GRPO”，而是先问 rrr 的来源和值不值得信任。

层次要回答的问题典型例子
训练起点从哪个模型继续？基座模型、SFT 模型
反馈来源什么算“更好”？人类排序、单元测试、对比提示
评分器如何把反馈变成数值？奖励模型、答案检查器、偏好模型
更新算法怎样提高高分回答概率？PPO、GRPO、DPO
验收真正交付时是否更好？盲测、留出题、红队、延迟与成本

把这些层次混称为“RLHF 算法”会掩盖关键风险。例如 DPO 通常直接用离线偏好对优化，并不必训练独立奖励模型，也不要求在线 PPO；它仍可使用人类、AI 或 RLCD 生成的偏好数据。关于 PPO、DPO、GRPO 的目标差异可继续阅读PPO / DPO / GRPO。

1.1 一个反馈源，对应不止一种训练闭环

“有偏好对”不自动等于“必须做在线强化学习”。以同一批 (x,yw,yl)(x,y_w,y_l)(x,yw​,yl​) 为例，可以训练奖励模型后让当前策略继续采样、再以 PPO 或 GRPO 更新；也可以直接用 DPO 一类的离线偏好目标更新。前者会看到模型现在最可能生成的答案，因而能继续探索，却要承担 rollout、奖励模型被利用和训练不稳定的成本；后者实现较简洁、训练信号固定，却受限于已有回答对的覆盖。

反过来，“使用 PPO”也不说明反馈来自人。PPO 可以优化人类偏好训练出的奖励模型、自动验证器或任意可计算评分。阅读论文或训练日志时，至少同时记录以下四项：候选由谁生成、谁提供偏好／判定、评分器是否学习得到、策略是否在更新中重新采样。 只有它们共同确定，路线名称才有可复现的含义。

2. RLHF：把难以写成规则的人的判断变成奖励

RLHF（Reinforcement Learning from Human Feedback）适合“正确”本身不足以定义品质的场景：回答是否有帮助、是否礼貌且不过度迎合、拒答是否合适、摘要是否忠实、长文是否结构清晰。其经典流程是：

  1. 先用高质量示范进行 SFT，得到能完成基本对话的策略；
  2. 让标注者对同一提示的多条候选进行排序或二选一；
  3. 用这些比较训练奖励模型 rϕ(x,y)r_\phi(x,y)rϕ​(x,y)；
  4. 策略在线生成新回答，由 rϕr_\phirϕ​ 打分，再做受约束的策略优化。

若同题两条回答中 ywy_wyw​ 被选为优于 yly_lyl​，常见的 Bradley–Terry 奖励模型损失是：

LRM(ϕ)=−log⁡σ(rϕ(x,yw)−rϕ(x,yl)). \mathcal L_{\mathrm{RM}}(\phi)=-\log\sigma\big(r_\phi(x,y_w)-r_\phi(x,y_l)\big). LRM​(ϕ)=−logσ(rϕ​(x,yw​)−rϕ​(x,yl​)).

它不要求评分器给出绝对的“87 分”，只要求优选回答的分数相对更高。InstructGPT 展示了“示范—人类比较—奖励模型—PPO”的代表性路径；原论文也提醒我们，反馈数据的收集协议是方法的一部分，而不是可忽略的附属品。InstructGPT 这是一条历史上重要的配方，不是“RLHF”一词强制规定的四步：人类也可以给标量评分、纠错或示范，训练也可以只停在偏好优化阶段。

2.1 优势不是“更像人”，而是可表达偏好

对开放式写作、危害边界、助人程度等任务，很难写出可靠的可执行判定器。人类比较能覆盖语气、事实呈现方式和情境取舍等细粒度价值；只要采样、标注指南和质量控制得当，它比“关键词命中”更接近用户体验。

代价是昂贵且有噪声。标注者之间会分歧，某种语言、文化或具体任务可能被覆盖不足；奖励模型还会被策略反复优化，从而出现“分数升高但人更不喜欢”的 reward hacking。缓解措施不是只增加 PPO 步数，而是保留盲测集、加入对抗提示、周期性重采样人类比较，并在评分器之外衡量事实性、安全和成本。

3. RLVR：把能核验的结果变成规模化练习

RLVR（Reinforcement Learning with Verifiable Rewards）将反馈交给验证器 vvv：数学最终答案是否等价、程序是否通过隐藏测试、定理证明是否经检查器接受、结构化输出能否通过 schema 或仿真约束。最简单的奖励可以是

r(x,y)=1[v(x,y)=pass], r(x,y)=\mathbb 1[v(x,y)=\mathrm{pass}], r(x,y)=1[v(x,y)=pass],

也可给部分分、测试通过比例或格式与正确性的组合分。关键性质不在“奖励是 0/1”，而在于训练时可以低成本、可重复地检查。这让同一个题目能采样多条轨迹，比较不同推理路径，并随训练不断产生新数据。验证器必须只读取允许的输出与工具痕迹；若模型能访问测试答案、污染运行环境或利用解析漏洞，得到的是测试器分数而不是任务能力。

DeepSeek-R1 将可验证的推理奖励与组相对策略优化结合，是理解这条路线的公开案例；它也包含冷启动、拒绝采样、SFT 和后续混合训练，不能把整套配方简化成“只跑一次 GRPO”。DeepSeek-R1 在 RLVR 中，GRPO 常通过同题 GGG 条回答的奖励构造相对优势，例如

Ai=ri−mean⁡(r1,…,rG)std⁡(r1,…,rG)+ϵ. A_i=\frac{r_i-\operatorname{mean}(r_1,\ldots,r_G)}{\operatorname{std}(r_1,\ldots,r_G)+\epsilon}. Ai​=std(r1​,…,rG​)+ϵri​−mean(r1​,…,rG​)​.

这减少了对单独 value critic 的依赖，却不会使信用分配自动变精细：若只检查最终答案，整条推理的 token 通常共享同一个结果信号。

3.1 验证器强，不等于任务定义完整

RLVR 的优点是吞吐和一致性。一个代码测试器不会疲劳，且能评价大量模型刚生成的新程序；因此它特别适合有明确外部判定的数学、代码、形式化证明与工具调用任务。

它的风险也集中在验证器边界。测试覆盖不到的 bug 仍会漏过；只看最终数值会容忍无意义或不安全的过程；格式检查可能被投机地满足；如果大部分题对当前模型都是全错或全对，组内相对奖励几乎没有学习信号。工程上要维护隐藏测试、对抗样例、执行隔离和难度分桶，并把“验证器通过率”与人类可读性、鲁棒性、推理长度和推理成本分开报告。

4. RLCD：用对比蒸馏合成偏好，而非假装有人工标签

本文的 RLCD 指 2023 年论文提出的 Reinforcement Learning from Contrastive Distillation。它面对的难题是：已有一组自然语言原则，例如“解释要有帮助但不能协助伤害”，却没有为每个提示收集人工排序。做法是对同一提示建立两个上下文：一个正向提示鼓励遵循原则，一个负向提示鼓励违背原则；分别由模型生成候选，将前者作为偏好候选、后者作为劣选候选，训练偏好／奖励模型，再用强化学习改善目标策略。RLCD 原论文

这是一种构造比较数据的方式，而不是证明 y+y^+y+ 在每个维度都客观更好：

x→违反原则c−y−,x→遵循原则c+y+⇒(x,y+≻y−). x \xrightarrow[\text{违反原则}]{c^-} y^- ,\qquad x \xrightarrow[\text{遵循原则}]{c^+} y^+ \quad\Rightarrow\quad (x,y^+\succ y^-). xc−违反原则​y−,xc+遵循原则​y+⇒(x,y+≻y−).

它和“让一个 AI 评审直接打分”的 RLAIF 有交集，却不完全相同：RLCD 的特别之处是用刻意相反的上下文拉开两种候选，以获得更清楚的比较边界。之后仍需决定是训练奖励模型后在线优化，还是把偏好对直接交给 DPO 一类目标；这些选择不能从缩写本身推断。

4.1 它省掉了什么，又引入了什么？

RLCD 降低的是逐条人工比较的需求，并能把原则扩展到大量提示；它没有创造外部真相。若正向／负向提示诱导出的差异只是套话，偏好模型会学会识别文风而非真正的无害性或帮助性。若教师模型漏掉事实错误或存在文化偏见，蒸馏会复制这些盲点。因而至少要用少量人工审计集、越狱与反例提示、跨分布测试来检查“原则是否真的被遵守”，而不是只汇报合成偏好训练的 loss。

同名提醒。 近期也有工作将 RLCD 写作 Reinforcement Learning for Calibrated Decisions，目标是让模型给出的概率与实际正确频率相符。它与本文的“对比蒸馏”不是同一方法、也不共享同一奖励定义。有关公开证据与校准评估的边界，见站内Jev 决策层。写实验报告时必须展开全称。

5. 横向比较：何时该选哪条？

路线反馈的原始来源最擅长的问题最常见误用必备验收
RLHF人类示范、排序、评分主观质量、社会规范、细腻取舍把奖励模型分数当真实用户满意度盲测偏好、分人群安全审计、奖励泛化
RLVR答案、测试、检查器、规则数学、代码、可验证工具任务把通过率当成完整行为质量隐藏集、对抗输入、过程与成本检查
RLCD（对比蒸馏）原则引导的正负候选原则已知但人工比较稀缺把合成标签当人类事实人工审计、提示鲁棒性、跨域偏好

若目标主要是“用户是否喜欢且感觉被恰当对待”，从少量高质量 RLHF 数据建立锚点通常更可靠；若目标有强判定器，RLVR 能以更低边际成本扩展；若希望把已有原则变成大量训练比较，RLCD 可作数据引擎，但应由人类审计闭环。很多生产系统会在通用助手阶段使用人类或 AI 偏好，在数学／代码子域加入验证器，在安全原则覆盖不足的地方使用对比生成，再以统一评测套件观察是否互相伤害。

5.1 用任务属性选反馈，而不是追缩写

先问三件事：结果能否由外部系统稳定判定？用户之间的合理取舍是否会分歧？已有原则能否可靠地诱导出正反例？答案分别指向 RLVR、RLHF 和 RLCD 的相对优势。一个任务若同时具备这些属性，优先把硬约束交给验证器，把软质量交给盲测或偏好评审；不要把可写成断言的约束寄托给奖励模型，也不要期待单元测试评判解释是否真诚清楚。

6. 一套不依赖缩写的实施清单

  1. 写出交付行为。 “数学正确率”“代码安全性”“解释有帮助”不是同一个目标，也不会由同一个奖励可靠覆盖。
  2. 先审计反馈器。 抽样检查人类分歧、验证器假阳性／假阴性，或对比提示是否只改变表面措辞。
  3. 分离训练、选择与测试。 用训练 reward 选 checkpoint 可以；最终结论要留给从未参与该选择的题目与人工盲测。
  4. 记录策略约束和采样协议。 参考模型、KL、温度、每题候选数、长度截断和拒绝采样都会改变结果。
  5. 报告副作用。 除主指标外，至少观察格式错误、拒答、长度、延迟、每请求成本及跨任务退化。

后训练没有一个“获得高奖励就结束”的通用终点。可靠的结论应当是：在清晰声明的提示分布、评分器和资源预算下，某个模型在独立评测中改善了哪些目标，又牺牲了哪些目标。理解 RLHF、RLVR 与 RLCD 的差异，正是把这句话说清楚的第一步。

阅读自测与验收

  • RLHF、RLVR 与 RLCD 是三种互斥优化器吗？ 不是；它们按反馈来源分类，PPO、GRPO、DPO 解决的是更新方式。
  • 程序测试通过就证明回答在所有维度都好了吗？ 不证明；隐藏测试、过程安全、可读性与成本仍要分别评估。
  • RLCD 产生合成偏好后就不需要人工审计吗？ 不需要；提示诱导与教师模型偏差仍会进入训练信号。
  • 本文的 RLCD 与校准决策 RLCD 是同一种方法吗？ 不是；必须展开全称，并分别核对奖励和证据。
  • 训练奖励持续提高可以代替独立评测吗？ 不可以；策略可能利用评分器漏洞或在未见分布上退化。
