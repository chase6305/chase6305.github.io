你对机械臂说：“把红色杯子放到蓝色托盘上。”相机里有杯子、托盘和夹爪，但机器人还需要知道下一刻该怎样移动、什么时候闭合夹爪，以及执行后要不要调整。VLA（Vision-Language-Action，视觉语言动作模型）要连接的，就是图像、任务文字与这些具体动作。

本文沿着这件事比较 RT-2、OpenVLA、π0，以及后续 π 系列。先看一次机器人决策，再看动作怎样编码和生成，最后解释训练数据、后训练与评估。每出现一个核心公式，都会先说明它正在解决什么问题。

0. 先跟着机器人搬一次杯子

桌上有一个红杯子和一个蓝托盘。人说：“把杯子放到托盘上。”这件事可以拆成靠近、抓住、抬起、移动、放下、松开，但一句任务指令并没有指定每个关节下一刻该转到哪里。VLA 要连接的正是这两种描述。

0.1 先分清“描述画面”与“选择动作”

视觉语言模型 VLM 接收图像与文字，可以回答“杯子在托盘左边”。视觉语言动作模型 VLA 进一步输出机器人接口能消费的动作，例如“末端沿指定坐标轴移动一点，夹爪暂时保持张开”。这里的“末端”指机械臂最前面的工具或夹爪；“本体状态”指机器人自己的关节角、夹爪开度等读数。

把 VLM 变成 VLA，通常需要两件事：一是定义动作怎样表示，二是用机器人示范训练图像、指令与动作之间的关系。认识“杯子”可以帮助选择对象；实际抓取还需要关于相机视角、机器人几何、接触与运动的经验。网页里的杯子图片通常没有附带当前机器人可执行的关节命令。

0.2 一次模型调用只负责接下来的一小段

假设夹爪还在杯子上方较远处，一轮闭环可以这样理解：

  1. 观察现在。 相机拍下杯子、托盘与夹爪；支持状态输入的模型还读取关节角和夹爪开度。任务文字仍是“把杯子放到托盘上”。
  2. 预测接下来的动作。 单步策略输出一个控制步，动作块策略输出一小段未来命令。此时合理的局部行为可能只是靠近杯子，并未完成整个任务。
  3. 执行一部分。 输出经过解码、单位转换等处理，交给机器人控制器。控制器根据实际反馈驱动关节，让机器尽量跟随命令。
  4. 重新观察再决定。 夹爪可能已经更靠近杯子，也可能受到遮挡或碰撞。下一轮必须根据新的画面与状态继续预测。

这就是“闭环”：执行改变世界，新的观测再影响下一次动作。它不要求每轮重新训练模型；普通部署时，更新的是观测和动作，模型权重通常保持不变。

1.1 模型看到的是观测，控制器执行的是命令

先看一个人为约定的单臂末端增量接口。下面一行表示同一个控制步中的七个量：

[dx, dy, dz, droll, dpitch, dyaw, gripper]
[0.02, 0, 0, 0, 0, 0, 1]

约定前三维单位为米、后三个旋转量单位为弧度、位移沿机器人基座坐标轴、夹爪 1 表示保持张开，那么它的意思是：末端沿基座 x 轴正方向移动 2 cm，保持姿态与张开的夹爪。这只是解释接口的数值，不是建议直接发送的真机命令；可执行步幅由平台与控制周期决定。

其中七个数字要一起构成一个动作，不能依次理解成七个时间步。“七维动作”也不等于“七个关节角”：这里是三维平移、三维旋转与一维夹爪。若接口改成关节目标位置，这些数字的含义就会整体改变。

把这种“一行”按未来时间排成一张表，就是动作块：行表示什么时候执行，列表示控制哪个量。例如 50 行、14 列，表示未来 50 个控制步，每一步有 14 个动作分量。原始 π0 的具体列定义取决于机器人，未必使用上面的末端增量接口。

14 列也可以具体理解：π0 论文中的双臂 Trossen 平台，每侧有 6 个机械臂关节量和 1 个夹爪量，两侧合计 14 个。这时一行控制的是两个机械臂的关节与夹爪；前面单臂例子的 7 列控制的是末端位姿增量与夹爪。数字个数相近，不代表列的物理含义相同。π0 机器人配置 §V-C

1.3 一条训练记录长什么样

机器人示范通常是一条 episode：操作者完成一件任务，系统按时间保存图像、状态、指令和动作。训练时再从里面截取观测与未来动作窗口。

还有三个数据边界要在截窗前处理：

  1. 不能跨 episode 拼动作块。 快结束时可以丢弃不完整窗口，或按明确规则补齐；补齐位置是否进入损失必须与实现一致。
  2. 动作命令不等于实测状态。 目标关节角与随后反馈的关节角会受延迟和接触影响，不能在不了解定义时互换。
  3. 不能把未来信息变成普通在线观测。 用未来帧形成目标图像可以作为特定训练条件，但部署时必须有可获得或可生成的对应条件；π0.7 正好会用到这个区别。

关于遥操作、UMI、人类视频与仿真分别能提供哪些监督，可接着看数据来源专题。

继续用杯子任务。假设一次遥操作持续 20 秒，以 50 Hz 记录，得到 1,000 个时间位置。每个位置保存当时的图像、状态和操作者发出的命令。如果动作块长为 50、每次向后滑动一个位置：

0第 0 帧、当前状态、任务文字第 0～49 行动作
1第 1 帧、当前状态、任务文字第 1～50 行动作
950第 950 帧、当前状态、任务文字第 950～999 行动作

训练时的“未来动作”来自已经录完的示范，模型可以拿它当答案学习；部署时只知道当前输入，需要预测这张动作表。数据加载器把未来动作读出来，不意味着机器人拥有预知未来的传感器。

1.5 控制器怎样接住模型输出

以刚才的末端增量为例，接口先把归一化数值还原到物理单位，再根据既定坐标系解释位移与旋转，最后交给对应的末端控制器。控制器可能结合逆运动学、伺服反馈等方法转成关节运动；若 VLA 已经输出关节目标，则走相应的关节控制接口。具体链路取决于平台。

因此，要把模型接到机器人上，必须让训练标签的含义与执行接口的含义一致。模型按“位置增量”学到的 0.02，不能被执行器当成“绝对位置”；按基座坐标表达的前进，也不能直接当成工具自身的前进。接口匹配是理解后面归一化、动作 token 和多机器人数据转换的起点。

1.6 只有图像，怎么输出三维运动

一个常见疑问是：照片只有二维像素，模型怎么知道该向前移动多少？对本文讨论的端到端策略，机器人示范提供了学习这种关系的监督。例如，训练样本反复出现某种相机视角下的夹爪、杯子位置，以及操作者接下来发出的三维动作。模型学习利用这些视觉线索和任务条件预测动作，不要求中间一定先输出一份显式三维地图。OpenVLA §3.1–3.2

但图像不能凭空补足看不见的信息。同一物体的大小、距离和遮挡可能产生歧义；改变相机位置或焦距，也会改变像素变化与运动之间的关系。多相机、本体状态、历史或深度信息各自能补充信息，是否接入要由模型接口决定。“直接预测动作”描述的是学习接口，并没有免除观测覆盖与部署匹配的问题。

2. RT-2：把机器人动作写进 VLM 的词表

2.1 它改变了视觉语言模型的哪一部分

普通生成式 VLM 接收图像和问题，输出“桌上有一个红色杯子”。RT-2 保留这种输入与序列预测机制，但把部分训练样本的答案换成动作编码。例如，一次动作包含：

terminate | dx | dy | dz | droll | dpitch | dyaw | gripper

连续维度先分桶，再映射到语言模型可以输出的 token。模型学习的是“看到这样的图像、收到这样的指令，接下来应该输出哪些动作编号”。

这里可以把 token 理解成模型词表里的一张编号卡。对于普通文字，编号卡对应一个词或词的一部分；对于动作，它对应某个数值区间。模型只负责预测该出哪张卡，解码器再把卡号还原为控制数值。分桶是把连续刻度尺切成小格，token 映射是给小格分配词表里的编号，两者是不同步骤。

动作当成文字 token，不等于让模型每次写带小数点的说明句。 token 最终有一个整数 ID，它的动作意义由编码器与解码器赋予。PaLI-X 已有方便表示整数的 token；PaLM-E 则重用低频词表项。两者都把动作输出纳入既有序列建模框架。RT-2 动作编码

2.3 训练目标仍然是 next-token prediction

假设一个动作需要输出八个符号。训练时，模型在看到图像、指令和正确的前缀后，学习预测下一个正确符号；部署时，它必须接着自己刚刚输出的符号继续预测。这就是自回归。一个符号接一个符号地生成，并不意味着机器人生成一个符号就动一下：应先得到完整、可解码的动作，再交给控制接口。

用三个位置缩短表示，区别如下：

要预测的位置训练时提供的前序动作推理时可用的前序动作
第 1 个尚无动作前缀尚无动作前缀
第 2 个数据中的正确第 1 个模型刚生成的第 1 个
第 3 个数据中的正确第 1、2 个模型刚生成的第 1、2 个

所有行还共同读取图像与指令。训练中使用正确前缀称为 teacher forcing；配合因果注意力，多个位置的训练预测可以在一次前向中并行计算。推理时后一个位置依赖前一个生成结果，才需要逐步解码。因此，“自回归输出”不等于“训练时也必须一个位置一个位置单独运行模型”。

训练还要有一个计分规则，称为损失函数（loss）。这里采用交叉熵：模型给正确 token 的概率越低，损失越大；训练通过调整参数，让正确答案获得更高概率。对一个确定的正确类别，这一项可以写成它的预测概率的负对数。

例如某个位置的正确答案对应第 153 号桶：模型给正确 token 的概率为 0.7，这一项损失为 −ln⁡(0.7)≈0.357-\ln(0.7)\approx0.357−ln(0.7)≈0.357；只给 0.02 时，损失约为 3.912。训练会推动模型提高正确 token 的概率。这个数值衡量分类预测，不能直接当成毫米误差；后者需要解码回动作单位再计算。

2.4 网页知识怎样参与动作学习

RT-2 并没有仅靠网页学会抓取。它继承预训练 VLM，再将机器人动作样本与原有视觉语言样本一起微调，称为 co-fine-tuning。网页侧保留视觉问答、描述与语义知识，机器人侧提供“当前观测对应怎样的控制动作”。

原论文中，RT-2-PaLI-X 和 RT-2-PaLM-E 的机器人样本混合比例分别约为 50% 和 66%，说明这不是把两个原始数据目录等量拼接。它仍是监督学习配方，不能因为模型控制机器人，就自动称为在线强化学习。RT-2 附录 B、E

理解迁移时，可以区分两件事：网页知识帮助确定“哪个物体符合任务描述”；机器人示范教会策略“怎样完成相应运动”。认识一个新物体的用途，不保证策略获得了机器人数据里从未覆盖的接触技能。

2.5 RT-2 留下的部署问题

原论文采用远程多 TPU 服务：55B 的 RT-2-PaLI-X 报告约 1～3 Hz，5B 版本约 5 Hz。它们是特定系统的控制运行结果，不是所有 VLA 的固定速度，也不等于底层电机伺服频率。RT-2 实时推理

对于低速抓取，这可能足够；对于高频双臂操作，如果每个标量都靠大型语言主干逐个生成，动作表示和推理调度就会越来越重要。这也是后续动作块、连续生成和压缩 token 研究的背景。

3. OpenVLA：开放模型，同时重新组织视觉与机器人数据

3.1 不是把 RT-2 的权重换成开源许可证

OpenVLA 基于 Prismatic VLM，视觉部分结合 DINOv2 与 SigLIP，语言主干使用 Llama 2 7B。同一张图像经两个视觉编码器得到特征，拼接后由 projector 映射到语言模型的表示空间，再与语言 token 一起处理。

这句话包含三个处理步骤，可以沿着杯子图像展开：

  1. 图像变成特征。 视觉编码器把图像中的区域转换成一组向量；每个向量是很多个浮点数，能够携带视觉信息，而不是一段“这里有杯子”的文字描述。
  2. 两路特征接起来，再对齐维度。 同一图像区域的两组特征沿特征维拼接。Projector 是可训练的小网络，把它们转成语言主干能接收的向量宽度；它不负责把像素坐标直接算成机械臂三维坐标。
  3. 图像与任务共同决定动作。 主干同时处理视觉表示与“把杯子放到托盘上”的文字表示，输出动作 token。动作损失会让这些模块逐渐适应“哪些视觉信息与下一步运动有关”。

所以“视觉 token”通常指序列里承载视觉向量的位置，未必是一个离散词表 ID；“动作 token”在原始 OpenVLA 中则是离散编码。相同的 token 一词，在论文中可能指不同层面的对象。OpenVLA §3.1–3.2

两个视觉编码器提供互补的表示，但不能把它们硬分成“一个只管位置、一个只管语义”。论文给出的动机是结合空间细节与语义信息；实际作用需要看消融实验。OpenVLA 架构与项目资料

3.2 开放数据也需要筛选、转换与重采样

OpenVLA 的主要训练集合来自 Open X-Embodiment，约 97 万条机器人轨迹。这里是 episode／trajectory 数，不是 97 万张图片，也不能与 π0 的“小时”或“时间步”直接做大小比较。

原版为了统一接口，筛选具有第三人称相机、适合单臂末端控制的操作数据，并按数据集设定混合权重。动作按训练数据每维第 1 与第 99 百分位数所界定的范围归一化，再转换为离散编码；部署必须使用匹配的统计量反归一化，夹爪等特殊维度按实现的 mask 与语义处理。模型只在动作输出位置计算动作预测的交叉熵，而不是把输入指令也当成动作目标。

这样的处理牺牲了一部分异构输入灵活性，换来较一致的训练问题。想把双臂、多视角、移动底盘数据直接接进去，就必须先修改输入输出与数据转换，不能认为“同属 OXE 格式”就会自动兼容。OpenVLA §3 与附录 A、OXE 项目

3.3 “7B 打赢 55B”应该怎样读

论文报告 OpenVLA 相比 RT-2-X 55B 在其机器人评估中的整体成功率有 16.5 个百分点的提升。“百分点”是绝对差值，不是相对增长 16.5%；原始 RT-2 与跨机器人数据训练的 RT-2-X 也不是同一个模型名称。

原文分别进行了 BridgeData V2 的 170 次试验（17 个任务各 10 次）和 Google robot 的 60 次试验（12 个任务各 5 次）。OpenVLA 在前者明显领先，在后者表现相近；这个差异应与整体数字一起读。

这个结果并不是只改参数量的消融。OpenVLA 与 RT-2-X 的机器人训练集合规模、数据清洗、视觉编码器和训练方式都有差异。论文还指出 RT-2-X 在语义泛化类别有优势。因此，这个结果支持“开放且较小的模型，在这一组实验中可以很有竞争力”，不能支持“参数越少越好”或“所有泛化能力都超过 RT-2”。OpenVLA §5.1

若自己设计公平比较，至少要同时记录：测试机器人与相机、任务及初始状态、训练任务是否重叠、推理频率、每个任务的试验次数、成功标准和置信区间。只在表格里并排写 7B 和 55B 不够。

3.4 原始训练配方：视觉部分也要适配动作

OpenVLA 原论文报告，最终训练使用 224 × 224 图像、全局 batch 2048、固定学习率 2×10−52\times10^{-5}2×10−5，约遍历数据 27 个 epoch；64 张 A100 训练约 14 天，合计约 21,500 A100·小时。这是通用模型训练预算，不是换一台机器人做 LoRA 所需的预算。

比背下这些数字更有用的是理解其消融：在论文的实验中，提高图像分辨率到 384 × 384 没有带来相应收益，却使训练约慢三倍；冻结视觉编码器也降低了机器人表现。原始 OpenVLA 因此会适配视觉编码器，而不是只训练末端的动作输出层。OpenVLA §3.4–3.5

这些结果依赖当时的数据与任务。它们不能推出“所有 VLA 都不需要高分辨率”，也不能推出“训练动作 token 准确率超过某个值就可以跳过真机评估”。视觉定位、动作编码和闭环控制仍是不同的验收环节。

3.5 开源带来的实际变化

有了开放权重、数据处理与微调代码，研究者可以检查归一化统计、替换机器人数据、做 LoRA 或全参数适配，并分析动作预测失败发生在哪一层。原始 OpenVLA 仍有单图像、单步输出等限制；OpenVLA-OFT 是后续配方，不应反过来写进 2024 年原版的功能列表。OpenVLA 官方仓库

3.6 换到自己的机器人，为什么不能只换模型文件

假设训练数据中某个位移维度的有效范围是 −5 cm 到 +5 cm，并按这个范围线性映射到 [-1,1]。那么归一化输出 0.4 对应 +2 cm。如果部署时误用了 −10 cm 到 +10 cm 的统计量，同一个 0.4 会还原成 +4 cm。网络输出没有变，机器人实际收到的位移却翻倍了。 这里的范围是人为例子，用来说明统计量为何属于模型接口。

迁移时可以按四个问题检查：相机里能否看到任务所需的信息；训练与部署的动作含义是否一致；归一化统计是否匹配当前数据；新环境是否需要示范来适配。LoRA 是减少可训练参数的一种方法，不能替代这四项检查。

继续用杯子任务：如果原训练画面从桌面前方拍摄，现在只提供腕部相机，杯子外观与空间关系都会变化；如果原来输出末端增量，现在控制器要求关节绝对位置，输出定义也变了。前者主要是观测分布适配，后者还涉及动作接口重设计。把它们都称为“换个机器人微调一下”，会掩盖实际工作量。

4. 动作为什么不直接回归？这个问题需要改写

这里的回归指直接预测数值，例如输出位移 0.02；前面的离散分类则为各个动作桶预测概率。MLP（多层感知机）是一种由多层全连接变换组成的常见神经网络，可以作为预测数值的输出模块。

动作当然可以直接回归。 更准确的问题是：在当前观测下，如果存在多种相互不同但都合理的动作，一个确定性输出与某种损失函数会学到什么？

4.3 Flow Matching 也用回归，为什么不矛盾

Flow Matching 的网络确实常用平方误差训练，但它回归的是给定噪声状态、流时间和观测时的向量场，不是只根据观测输出唯一的最终动作。不同初始噪声可以经过同一向量场抵达不同动作，因此最终策略仍能表达条件分布。

生成模型也不自动保证动作安全、平滑或成功。它可能准确复现低质量示范中的犹豫和错误；如果数据本身集中、目标任务单一，简单回归可能是很强的基线。后续 OpenVLA-OFT 使用 L1 回归取得良好结果，正好说明应通过实验选择，而不是把“生成式”当成必然优胜的标签。

5. π0：动作专家不是一个普通线性输出头

到这里，RT-2 和原始 OpenVLA 已经能把图像与指令转成一行离散动作。π0 关心的是：能否直接生成一整张连续动作表，让相邻时间位置共同形成一段运动？ 它仍然需要视觉语言理解，但为动作部分增加了一套专门的网络与生成方法。

5.1 继承语义主干，新增连续动作计算

π0 使用约 3B 参数的 PaliGemma 初始化视觉语言部分，再增加约 300M 参数的动作专家，总规模约 3.3B。新增部分不只是最后一层线性投影，而是一套处理机器人状态与动作位置的 Transformer 权重。

“专家”在这里首先表示一组专门处理这类输入的参数。视觉语言部分为“画面里有什么、指令要求什么”提供条件表示；动作专家把当前的动作表、流时间和这些条件结合起来，预测整张表该怎样更新。动作专家不是在外面等主干发一句聊天消息，也不是一张查找现成技能的规则表。

模型可以理解为两组按模态分工的权重：

  • 图像和语言位置使用 VLM expert，继承已有预训练。
  • 机器人状态和动作位置使用 action expert，学习连续控制。
  • 两组表示通过注意力交互。这里不是常见稀疏 MoE 的“每个 token 由学习到的 router 任意选 top-k 专家”，分工主要由输入模态确定。

π0 没有在推理时先完整生成一句文字计划，再把那句话送入一个独立动作网络。 原始低层策略可以直接把视觉、语言、本体状态作为条件生成动作；高层任务分解属于另一个需要说明的使用层次。π0 §IV 与附录 B、PaliGemma

这也解释了“连续动作头”为什么有不同实现：简单回归头可以一次直接给出最终表格；π0 的动作专家给出的是每次生成迭代所需的更新速度，经过多次调用才得到最终表格。两者都能输出连续值，训练目标与推理过程却不同。

同一动作块的所有位置可以相互注意，以共同形成时间上协调的行为。不过，双向注意力本身不是碰撞约束，也没有证明生成轨迹一定满足动力学。

把 K/V 暂时理解成注意力计算中可复用的中间结果即可。对同一张杯子照片生成一块动作时，图像没有在每次内部迭代后改变，所以与固定前缀有关的计算可以复用；机器人执行后换成新照片，下一块动作的相应上下文就要重新计算。缓存省的是重复处理同一条件的计算，不会把旧照片变成新观测。

6. Flow Matching：把整块噪声推成整块动作

这一节先用动作表讲过程，再给出公式。第一次阅读，只要能回答三件事就可以继续：网络每次修改什么，训练答案从哪里来，为什么生成迭代与机器人运动不是同一个时钟。后面的 6.4–6.12 进一步解释概率分布、张量和数值误差。

先不看公式：电脑里有一张尚未执行的动作表

设模型准备输出 50 行、14 列的动作。Flow Matching 的部署过程可以这样看：

  1. 准备同样大小的随机数表。 每个格子先放一个高斯随机数。这是采样的起点，暂存在计算机中，不会直接发送给机器人。
  2. 让网络看当前表格与条件。 输入包括这张表、当前流时间，以及图像、指令、本体状态等条件。网络输出另一张同形状的表，表示各格子随流时间的变化速度。
  3. 按一个小步长修改整张表。 所有 50 行、14 列一起更新。然后把新的表格和新的流时间送回同一个网络，继续更新；网络权重在这个过程中不变。
  4. 完成生成后再解释成动作。 走到数据端得到最终动作块，再按既定规则反归一化、转换，并执行其中一部分。随后获取新观测，开始下一轮。

“流”描述的是一群随机初值如何在学习到的速度场中移动，最终形成动作分布；“匹配”描述训练时让预测速度接近构造出来的速度标签。这里并没有向真实机械臂施加随机抖动，再观察它能不能自己回到目标。

初始噪声提供了不同的生成起点。对于固定的条件、模型参数与确定性求解器，重复使用同一张初始表，会沿同一计算过程得到相同输出；换一张噪声表，才可能采到另一种合理动作。标准高斯方便抽样，并不表示机器人示范的最终动作必须服从高斯分布。

因此，把代码中的随机表直接换成全零表，会改变部署时的采样方案。它仍可能产生一个动作，但无法再通过不同初值表达多种选择，需要单独评估。这些随机数位于归一化动作空间，不是给相机图像加噪声，也不是要求电机先随机运动。

网络怎样学会修改：先用示范构造练习题

训练数据里有一张操作者实际给出的动作表，记为 AAA。我们另外抽一张随机数表，把两张表按某个比例混合：有时保留很多动作结构，有时几乎全是噪声。因为训练程序知道两个端点，就能算出这条混合路径的速度，把它当作监督答案。

网络拿到的是混合后的表、混合比例对应的时间、当前任务条件。它预测速度，训练程序比较预测与答案之间的差异，再用优化器修改网络参数。一次样本只需在随机抽到的时间位置学习，通常不用先完整生成一遍动作块。

很多示范、很多随机数、很多时间位置共同训练出一个速度网络。部署时不再有真实动作表，也没有现成的速度答案；只能从随机表出发，多次查询这个网络。这和分类器训练时能看到类别标签、部署时要自己预测类别，是同一类训练／使用分工。

为什么必须告诉网络流时间？ 同一个数值，在接近纯噪声与接近最终动作时，含义并不相同。时间让网络知道当前处在生成过程的哪个位置；图像和指令则告诉它正在解决哪个机器人任务。

6.5 学到的是平均速度，为何终点不是平均动作

线性插值给出了很多条训练路径。每条路径由一对真实动作 AAA 和随机噪声 ϵ\epsilonϵ 决定，路径上的监督速度 U=ϵ−AU=\epsilon-AU=ϵ−A 是常量。但是，网络只看到当前 XsX_sXs​、时间 sss 和条件 ccc，不会同时收到这条路径的两个端点。这里用 ccc 统一表示图像、语言与本体状态。

不同训练路径可能经过相近的状态，却要求不同的速度。这时平方误差的最优解是什么？记 Z=(Xs,s,c)Z=(X_s,s,c)Z=(Xs​,s,c)，并记 Uˉ(Z)=E[U∣Z]\bar U(Z)=\mathbb E[U\mid Z]Uˉ(Z)=E[U∣Z] 为给定这些输入后的平均速度。将误差分解：

E[∥v(Z)−U∥2]=E[∥v(Z)−Uˉ(Z)∥2]+E[∥U−Uˉ(Z)∥2]. \begin{aligned} &\mathbb E[\|v(Z)-U\|^2]\\ &=\mathbb E[\|v(Z)-\bar U(Z)\|^2]\\ &\quad+\mathbb E[\|U-\bar U(Z)\|^2]. \end{aligned} ​E[∥v(Z)−U∥2]=E[∥v(Z)−Uˉ(Z)∥2]+E[∥U−Uˉ(Z)∥2].​

第二项不依赖网络。因而最优速度场是：

v∗(x,s,c)=E[ϵ−A∣Xs=x,s,c]. \begin{aligned} &v^*(x,s,c)\\ &=\mathbb E[\epsilon-A\mid X_s=x,s,c]. \end{aligned} ​v∗(x,s,c)=E[ϵ−A∣Xs​=x,s,c].​

关键在条件中的 xxx 和 sss。直接动作回归只有 ccc，最优输出是 E[A∣c]\mathbb E[A\mid c]E[A∣c]；Flow Matching 在不同位置、不同流时间会得到不同的平均速度。它把一整群噪声样本搬运成动作分布，并不要求每个噪声样本沿训练中某一条指定直线走到一个预先指定的动作。

也因此，训练路径是直线，不等于最终学到的采样轨迹都是直线。多条条件路径汇总后的边际速度场通常随位置和时间变化，沿它积分可以产生弯曲轨迹。“直线插值所以一步就能生成”缺少这个关键环节。

从密度的角度看，设 ps(x∣c)p_s(x\mid c)ps​(x∣c) 是插值变量的分布，合适的边际速度满足连续性方程：

可以依次做三个小观察：只改 N，动作间隔与名义覆盖时长都不变；保持频率、缩短 E，重新观察的理想间隔变短；保持 H、降低频率，同样数量的动作会覆盖更长时间。实际系统还要把推理耗时放回时间线，不能用这里的理想频率替代测量。

这个例子还没有解决块之间的等待：下一轮推理期间，执行系统需要定义如何保持或继续消费队列中的命令。异步调度可以在执行上一块时提前算下一块，但必须处理“新块返回时，预测开头已经过期”的对齐问题。隐藏计算耗时，并不会自动消除观测年龄；这也是 RTC 要研究的事情。

最后，动作块在策略层暂时不更新视觉条件，不等于所有控制层都停止反馈。底层关节伺服仍可根据编码器读数跟踪目标。说一段执行是“开环”还是“闭环”时，应明确是指视觉策略层，还是指关节控制层。

8. π0 的数据与训练配方

前面解释了“一条样本怎样产生损失”，这一节解释“这些样本从哪里来、按什么顺序训练”。两者不能互相替代：写对 Flow Matching 公式，只说明学习目标定义好了；机器人能否在陌生桌面抓住杯子，还取决于训练覆盖了哪些画面、动作与接触状态。

8.1 三种“预训练／后训练”不要混为一谈

阶段数据与监督学到什么
VLM 预训练，π0 继承其结果大规模图像、文本及视觉语言任务视觉表征、语言理解与语义关联
机器人通用预训练多机器人、多任务观测与动作把已有表征接到机器人动作空间，并覆盖不同场景和行为
任务后训练更聚焦、质量更高的机器人示范提高目标任务的流畅度、稳定性与完成质量

沿杯子任务读这三行：第一阶段让主干获得杯子、托盘、位置关系与语言的表示；第二阶段用不同机器人的动作记录，学习这些条件怎样联系到运动；第三阶段针对目标机器人与任务继续训练，让拿取、移动和放下更稳定。各阶段继承前面的权重，数据与训练目标可以变化。

例如，机器人通用预训练和任务后训练都可能使用“观测＋动作窗口”的样本，并都使用 Flow Matching。后训练之所以叫后训练，是因为它从已有通用策略出发、围绕更具体的目标继续优化，不是因为它必然换了一种损失函数。

原始 π0 的任务后训练主要是监督模仿学习，不等于后来 π*0.6 的强化学习。post-training 描述训练所处阶段，不能仅凭这个词判断用了 PPO、DPO 或奖励模型。

8.2 原始论文公开了哪些数据口径

π0 初版论文描述的自有数据覆盖 7 类机器人配置、68 类任务、约 10,000 小时以上的机器人经验，并结合开放机器人数据。正文给出自有数据约 903M 个时间步，其中单臂约 106M、双臂约 797M；公开数据在训练混合中约占 9.1%。这些数字服务于不同统计口径，不能互相替代。π0 §V 与数据概览、项目说明

特别要避免三种误读：

  • 时间步多不等于独立行为多。 50 Hz 数据每小时有 180,000 个记录步，5 Hz 只有 18,000 个；数据频率本身就能造成十倍差异。
  • 采样占比不等于磁盘占比。 混合训练会重采样，不应把 9.1% 自动解释成原始文件大小或小时占比。
  • “任务”不是统一计数单位。 “收桌子”可能包含分类、抓取、放置和处理多种物品；另一数据集可能把每个动词与物体组合单列一个任务。

8.3 混合权重怎样避免大数据源淹没小数据源

假如一个数据源大量记录搬杯子，另一个只录了少量拧瓶盖。直接把所有窗口混在一起等概率抽取，模型很少会遇到瓶盖。为每组数据指定采样概率，就能控制“每个训练 batch 里，通常能看到哪些任务”，而不必通过复制文件来调整比例。

初版论文按 task–robot 组合的样本数 nin_ini​ 设置与 ni0.43n_i^{0.43}ni0.43​ 成比例的采样权重。把它写成归一化概率：

pi=ni0.43∑jnj0.43. p_i=\frac{n_i^{0.43}}{\sum_j n_j^{0.43}}. pi​=∑j​nj0.43​ni0.43​​.

这是组合级采样概率，不是把同组每个样本再各乘一次 ni0.43n_i^{0.43}ni0.43​。若两个组分别有 100 万和 1 万个样本，原始数量比为 100∶1，幂次重采样后的组权重比约为 1000.43≈7.24100^{0.43}\approx7.241000.43≈7.24∶1。

如果只有这两组，后一种采样方式让小组的出现概率约为 12.1%，而按原始数量抽样只有约 0.99%。它增加了小组被看到的机会，但没有创造新的瓶盖示范；反复看到相同样本与采集更多不同情况仍然是两件事。

这个例子说明重采样如何减轻失衡，不表示 0.43 是适用于所有机器人数据的最优指数。实际还要考虑任务难度、不同频率产生的重复程度，以及某些小数据集是否过度重复。π0 数据混合

8.4 不同机器人怎样放进一个 batch

多具身训练至少要统一四层：

  1. 观测布局：相机顺序、裁剪分辨率、缺失相机 mask、状态字段。
  2. 动作语义：关节目标还是末端增量，坐标系、单位、夹爪符号、底盘控制。
  3. 数值尺度：根据训练数据估计统计量，保存归一化和反归一化规则。
  4. 张量形状：对不同维度做 padding 或其他结构适配，并约定损失如何处理补齐位置。

π0 原论文将状态与动作补到最大机器人维度 18；本文核对的 openpi 配置默认 action_dim=32、action_horizon=50，具体任务配置又可能覆盖这些值。18 和 32 属于不同版本与配置口径，不是论文自相矛盾，也不是“所有机器人都有 32 个动作自由度”。原论文 §V-A、固定版本 Pi0Config

把张量补到同样长，只解决形状问题；它不会把米自动变成弧度，也不会让左臂关节 1 自动对应另一个机器人的右臂关节 1。

例如，一个简化接口有 7 个有效动作量，另一个有 14 个。为了放进同一个数组，可以把前者补成 14 列，但补出的 7 列并不对应新出现的电机；恢复到第一台机器的执行接口时，只能按其定义取出有效字段。训练损失是否忽略补齐列，则要看具体配方，不能仅凭“这里填了 0”推断已经有了 mask。

8.5 为什么预训练保留多样性，后训练强调一致性

通用预训练希望看到更多状态、物体、机器人和行为变化，让模型具备覆盖面；任务后训练则希望示范动作更连贯、策略更一致，减少不必要的停顿和反复试探。

两者并不矛盾：如果只保留最顺利的示范，可能缺少处理偏差状态的经验；如果所有数据不分质量地一起模仿，又可能学到迟疑和失败。原始 π0 通过分阶段的数据选择缓解这种张力，后续 π*0.6 与 π0.7 分别进一步引入价值估计和行为条件信息。

论文的下游任务数据量从较简单任务约 5 小时到复杂任务 100 小时以上不等，不能据此承诺“自己的机器人只要录五小时就能叠衣服”。初始权重、硬件、任务难度、示范质量和评估环境都不同。π0 后训练说明

8.6 训练步数与模型大小为什么要一起看

π0 初版论文的主要通用模型训练 700k 步，也报告了训练 160k 步的版本，用于观察较小训练预算下的表现。不同曲线若使用不同训练步数，比较的就不只是网络结构。π0 §VI-A

论文还使用约 470M 参数的 π0-small 对照 VLM 初始化的模型。这个对照同时改变语言编码器、视觉与动作模块的结构和参数规模。因此，它能支持所比较的完整方案有差异，但不能单独把全部收益归因于“网页知识”一个因素。π0 附录 C

训练步数、batch、采样权重与动作窗口高度相关。同样 700k 步，若每步样本量和来源不同，实际训练工作量与数据暴露量就不同；相邻重叠窗口也不能按独立轨迹计数。

一个 batch 是同时用于一次更新的一组样本。例如 batch 为 8、动作块为 50 × 14，目标动作数组就有 8 × 50 × 14 个标量。一次优化器更新通常叫一个训练 step；遍历一遍有限训练集合叫一个 epoch；checkpoint 保存的是模型参数及所需状态。这些词都不等于机器人走了一步，也不等于一次 Flow Matching 采样。

在重新采样的数据混合或在线生成的算例中，epoch 未必有唯一清晰的含义。此时同时报告训练更新数、全局 batch、实际抽样量和数据来源，比只说“训练了很多轮”更可复查。

9. 两条重要分支：FAST 与 OpenVLA-OFT

走到 π0 并不意味着其他动作表示失效。下面两项工作恰好分别追问：能否把动作序列压得更短，继续使用语言式预测；能否直接并行输出连续动作，用更简单的损失得到好的控制？

9.1 FAST：动作 token 没有被连续模型淘汰

如果一个动作块有 50 步，每步 14 维，朴素逐标量编码就需要约 700 个动作 token，尚未计入其他标记。高频动作的相邻时间步往往很相似，逐个写出来既冗长，也让大量 token 都在重复局部细节。

2025 年 1 月的 FAST 换了编码对象：先对整段归一化动作沿时间做离散余弦变换（DCT），将时序结构转换为频率系数，再量化、排列并用 BPE 压缩为较短 token 序列。解码时逆转这些步骤，恢复连续动作块。

用夹爪的一列动作理解：如果连续 50 个位置都几乎保持同一开度，逐个编码会反复表达类似的数值；变换到频率表示后，常量或缓慢变化的部分可以用较集中的系数来描述。理想的严格常量序列只有直流系数非零。BPE 则把经常一起出现的符号组合成更长的词表单元。这里压缩的是动作序列的表示，不是把机器人真正要执行的 50 个控制周期删掉。

如果动作突然变化，高频系数也可能很重要；如何量化和编码会影响还原误差。因此，FAST 的“短 token 序列”与执行端的“完整动作块”可以同时成立，不能拿 token 数直接当作物理控制步数。

这条路线仍然可以采用 next-token prediction。它说明真正的问题不只是“离散还是连续”，还包括怎样把动作的时间结构编码进去。不过，量化可能有损，训练加速也不等于在线推理同样加速；官方资料明确指出 π0-FAST 的自回归推理比原始 π0 的流匹配解码慢。FAST 项目与论文

9.2 OpenVLA-OFT：直接回归也是有效路线

2025 年的 OpenVLA-OFT 把并行动作解码、动作块、连续动作表示和 L1 回归组合起来，适配多图像与本体状态等输入。它没有要求“只有 Diffusion 或 Flow Matching 才能做高频动作”。

论文在特定 LIBERO 和 ALOHA 评估中报告良好结果。理解这个工作时，应把“采用一个更适合任务的输出与微调配方”放在核心位置，不要只记一个榜单分数，更不要把这些设置误写成 2024 年 OpenVLA 原版已经具备的能力。OpenVLA-OFT 论文、项目中的 L1 与生成模型讨论

由此得到一个实用分类：离散动作＋自回归、连续动作＋确定性回归、连续动作＋生成式采样，是可以并行研究的设计选择。 采用哪一种，要同时看训练数据、任务多峰性、控制频率、推理延迟和成功率。

10. π0.5：让策略走进没有采集过的房间

10.1 改进目标从“会做”转向“换地方还能做”

π0 已经展示多种复杂操作，但在训练场景里完成任务，与走进陌生家庭完成同类任务，是不同难度的目标。π0.5 于 2025 年 4 月提出的重点是 open-world generalization：在未见过的环境中执行已有任务族。 它不等于对任意新技能、任意新机器人都无需数据。π0.5 项目说明

“语言指导”也不等于再次遥操作每个关节。操作者可以说“先把枕头拿起来”，由已有低层策略执行，从而记录高层决策应该如何随场景推进。

“混合数据”不要求每条样本都拥有同样的答案。一张杯子照片配“杯子是什么颜色”的问题，答案是文字；一条机器人示范，答案可以编码成 FAST 动作 token；当前场景配“收拾桌面”，高层答案可以是下一条子任务。预训练把这些输出纳入离散序列学习，后训练再为有动作监督的样本加入连续动作学习。缺少机器人动作标签的网页样本，不能通过补一串零就变成“机器人应该不动”的示范。 哪些位置计算哪种损失，需要随样本类型与训练阶段一起定义。π0.5 §IV-A–D

10.3 同一模型可以承担两种推理任务

先看杯子任务中的两类答案。高层输出可能是“先抓起杯子”；低层输出则是一张数值动作表。杯子已经在夹爪里后，高层可以换成“移动到托盘上方”，而低层继续根据最新图像与状态生成运动。子任务文字会在多轮低层动作生成期间保持有用，不需要每发一行动作就重新写一次。 这些文字只用于说明分工，不是论文实验记录。

把总任务记为 ℓ\ellℓ、当前子任务记为 ℓ^\hat\ellℓ^：

pθ(A,ℓ^∣o,ℓ)=pθ(ℓ^∣o,ℓ) pθ(A∣o,ℓ^). \begin{aligned} &p_\theta(A,\hat\ell\mid o,\ell)\\ &=p_\theta(\hat\ell\mid o,\ell)\, p_\theta(A\mid o,\hat\ell). \end{aligned} ​pθ​(A,ℓ^∣o,ℓ)=pθ​(ℓ^∣o,ℓ)pθ​(A∣o,ℓ^).​

第一项先回答“现在该做哪一步”，第二项回答“这一小步怎样移动”。例如：

总任务：收拾桌面
当前子任务：把空杯子放到水槽
低层输出：未来一段关节、夹爪与底盘动作

这是高层语义决策与低层连续控制的分工；高层通常没有必要按每个 20 ms 控制周期重写一遍指令。模型权重可以共享，但两种推理调用的输出、频率与评估指标仍然不同。

10.4 原始两阶段配方与后来的知识隔离

这里要区分两个层面：训练顺序决定先用哪些数据和输出形式建立能力；梯度路径决定一次损失会改动哪些模块。前者像安排训练阶段，后者是具体的参数更新规则。理解这两层，才容易看清原始 π0.5 与后来的知识隔离有什么关系。

π0.5 原论文的流程是：先用 FAST 等离散输出进行通用训练，再在后训练中加入连续动作专家，同时保留文字／离散输出监督。论文报告前者约 280k 次更新、后者约 80k 次更新；这些是原实验的训练步数，不是公开微调脚本的统一默认值。π0.5 §IV-D

随后 2025 年 5 月的 Knowledge Insulation（知识隔离，KI） 进一步明确一种训练配方：

  • VLM 主干通过文字与离散动作 token 的交叉熵得到训练信号。
  • 连续动作专家通过 Flow Matching 学习，并读取主干的条件表示。
  • 阻断动作专家损失回传到 VLM 主干的梯度，减少随机初始化的连续模块对既有表示的扰动。

可以将梯度关系概括为：

hˉ=stopgrad⁡(hθ(o,ℓ)),L=LCE(θ)+λLFM(ϕ;hˉ). \begin{gathered} \bar h=\operatorname{stopgrad}(h_\theta(o,\ell)),\\ \mathcal L=\mathcal L_{\mathrm{CE}}(\theta) +\lambda\mathcal L_{\mathrm{FM}}(\phi;\bar h). \end{gathered} hˉ=stopgrad(hθ​(o,ℓ)),L=LCE​(θ)+λLFM​(ϕ;hˉ).​

其中 θ\thetaθ 表示主干参数，ϕ\phiϕ 表示动作专家参数，hˉ\bar hhˉ 是阻断梯度后的条件表示。这个式子强调优化路径，省略具体注意力与输出分支。

可以沿同一个杯子样本看两种反馈：动作 token 预测错了，交叉熵的梯度可以修改主干，让它更好地表示动作所需信息；连续速度预测错了，Flow Matching 的梯度修改动作专家，但在隔离边界停止。动作专家在前向计算中仍读得到主干表示，主干也仍在被另一种损失训练。能读取一个表示、能用自己的损失修改这个表示的生成网络，是两个不同的权限。

Stop-gradient 不等于冻结整个 VLM。 主干仍被交叉熵训练；被阻断的是来自指定连续动作分支的梯度。也不代表推理必须先生成整串 FAST 动作，再交给动作专家——训练监督通道与部署动作解码通道可以不同。KI 论文、KI 方法说明

梯度隔离之外，还需要注意力隔离。连续动作分支不能读取训练中由 teacher forcing 提供的真实 FAST 动作 token，否则就可能通过另一种编码直接看到动作答案。Stop-gradient 只阻断反向梯度，不会删除前向信息；两类限制解决不同问题。原始 π0.5 的联合离散／连续训练已明确用 attention mask 隔开这两种动作表示。π0.5 附录 E

本文核对的 openpi 快照与原始研究全流程也要区分：该版本 README 说明 π0.5 的训练与推理接口支持的是 flow matching head，不能把论文中的全部异构联合训练过程都视为已经开放的可复现脚本。固定版本的 openpi 模型说明

10.5 状态与流时间的接入位置也变了

π0.5 原论文明确将本体状态离散化后作为文字 token 输入。进一步对照固定版本 openpi，可看到两个具体差别：

位置π0 路径π0.5 路径
本体状态连续状态投影，放在动作侧 suffix离散状态随文字进入主干 prefix
流时间时间嵌入与每个动作表示拼接，再经 MLP用时间条件调制动作专家中的 adaptive RMSNorm

第二项仍然告诉模型“当前噪声程度是多少”，改变的是信息注入网络的位置。第一项则会影响状态的数值表示、序列长度和可缓存区域。这说明升级版本时，应一起查看 tokenizer、attention mask 和输入转换，不能只替换 checkpoint 文件。π0.5 §IV-A、openpi Pi0Config、embed_suffix 实现

这里的 prefix／suffix 可以先理解成两组序列位置：前一组装本轮固定的观测条件，后一组装动作生成所需的信息。π0.5 把状态移到前一组，并没有把连续关节读数直接当成一句自然语言；它先把数值离散化，再按约定编码为 token。

Adaptive RMSNorm 怎样传入时间？ RMSNorm 先按特征向量的均方根调整内部数值尺度；自适应版本再由时间条件计算缩放、偏移和残差门控，使网络在不同流时间以不同方式处理特征。这发生在网络内部，不是第 1 节将动作还原成米、弧度的反归一化。同一组已训练参数可以根据不同的时间输入产生不同调制值，因此采样时无须为每个时间点重新训练网络。固定版本的归一化与 Transformer 实现

10.6 论文怎样验证“换地方还能做”

π0.5 的环境数量实验使用 3、12、22、53、82、104 个训练地点，再在未见的家居测试场景中评估。论文称这些场景为 mock home：它们是为便于重复比较而搭建的实体厨房、卧室布置，由真实机器人执行；另有真实住家的最终评估。为控制实验成本，这组消融没有为每个地点数重跑完整主配方：先在不含移动操作数据的机器人动作混合上预训练，再进行 40k 步后训练，作者据此控制各组见到的独特样本量。π0.5 §V 与 §V-B

它分别记录两个容易混淆的指标：语言遵循率看是否选对指令指定的物体；任务成功率还要求把它正确放到目标位置。选对杯子但中途掉落，可以在前一项上成功、后一项上失败。

此外，论文分别去掉网页数据、多环境固定机械臂数据和实验室跨具身数据，观察端到端进度与语言遵循。这样的对照比“加入很多数据后总分更高”更能说明来源的作用，但结论仍限于论文实际控制的训练与测试设置。π0.5 §V-C

11. π0.6 与 π*0.6：从模仿示范走向利用执行经验

11.1 先分清底座版本与 RL 配方

π0.6 延续视觉语言主干＋连续动作专家的路线，在相关技术报告中使用 Gemma 3 4B 主干，并将动作专家扩大到约 860M 参数，同时扩展机器人训练数据。

π*0.6 中的星号强调结合 RECAP 的强化学习训练版本。不能把 π0.6、π*0.6 与某个任务专用 checkpoint 当成完全相同的名称，也不能把“动作专家更大”和“从奖励反馈中学习”混成同一个改动。π*0.6 论文 §V

11.2 为什么成功示范还不够

对于模仿学习，训练答案来自“操作者当时做了什么”；对于利用执行结果的学习，还要问“这样做后，任务有没有更快、更可靠地完成”。实际部署会遇到策略自己造成的偏差：夹杯子时滑了一下，或者衣物折到一半变形。此时重新调整夹爪可能很有价值，但理想的成功示范里未必经常出现这种状态与补救动作。

只把失败轨迹直接加入行为克隆，会产生一个新问题：模型也可能把失败动作当成值得模仿的标签。因此需要区分这条轨迹提供了哪些状态覆盖和其中哪些行为值得增加概率。

11.3 RECAP 的经验闭环

RECAP 全称为 RL with Experience and Corrections via Advantage-conditioned Policies。其核心流程是：

  1. 执行当前策略，记录结果；必要时由人接管纠正。
  2. 将示范、自主执行与纠正数据用于训练价值函数。
  3. 利用价值估计与奖励，估计动作的 advantage，并构造条件标记。
  4. 训练带 advantage 条件的策略；部署时请求更优行为，再收集新的执行数据。

这里的价值函数回答“从当前状态继续做，预期能达到什么结果”。Advantage 则是在相应参考下，某个动作比基准预期好多少；它不是模型看见一个画面就直接读出的真实成功概率。RECAP 方法说明

可以把三个量分开记：奖励是这一步或这次结束得到的评分；价值是从某个状态往后走的预期累计评分；优势比较采取一段动作后的结果与原来的预期。三者的单位与数值范围由奖励设计决定，所以一个负价值未必表示模型“没有信心”，也可能只是预计还要花很多步骤才能完成。

用一个省略折扣、终止边界与实际归约细节的 nnn 步例子表示：

A^t=∑k=0n−1rt+k+V(ot+n,ℓ)−V(ot,ℓ). \begin{aligned} \widehat A_t&=\sum_{k=0}^{n-1}r_{t+k}\\ &\quad+V(o_{t+n},\ell)-V(o_t,\ell). \end{aligned} At​​=k=0∑n−1​rt+k​+V(ot+n​,ℓ)−V(ot​,ℓ).​

真实实现必须处理 episode 结束、超时与价值估计误差。论文进一步将估计优势转成二值条件标记来训练策略，而不是要求对整条 flow 采样链直接套用普通 next-token PPO。

这个二值条件可以理解成把训练数据按“相对基准更好”与“其余行为”加上不同标记。训练时，标记根据已经发生的结果与价值估计产生；部署时，策略接收请求更优行为的标记，再生成动作。它不需要先知道本次尚未执行动作的真实回报。这里的 A^t\widehat A_tAt​ 表示一个优势估计标量，与前文表示动作表的 AtA_tAt​ 含义不同。

11.4 奖励、价值与优势标签怎样落到数据里

RECAP 使用 episode 成功／失败标签构造奖励：普通非终止步骤为 −1-1−1，成功终止为 0，失败终止为 −Cfail-C_{\mathrm{fail}}−Cfail​，其中失败惩罚足够大。成功轨迹的未折扣回报因此与“距离完成还剩多少步”的负值相关；失败不会因为结束得早就被当成优秀的快速完成。

价值模型用轨迹后缀的实际累计回报做监督，并按任务的最大 episode 长度归一化。报告采用 201 个离散价值桶与交叉熵训练，再用桶概率的加权平均得到连续价值。其约 670M 的 VLM 底座小于策略主干；这是一份单独训练的价值模型，不是动作专家直接输出的自信分数。RECAP §IV-A、V-C

更新过程同样值得记录：论文在每轮聚合数据后，从预训练 checkpoint 分别微调价值模型和策略，而不是默认从上一轮任务模型接着训练；作者这样做是为了减轻多轮漂移。这属于具体实现选择，不能从“迭代强化学习”四个字自动推断。RECAP §IV-B、V-D

11.5 成功率之外还优化吞吐

该研究的奖励设计同时考虑完成与耗时：普通步骤产生时间代价，成功终止和失败终止得到不同处理。因此，一个更快且可靠完成的轨迹可以比反复犹豫的轨迹更优。

评估时也必须把成功率与完成速度一起报告。比如某策略成功率提升，但每次耗时翻倍，它每小时完成的合格任务数未必增加；反过来，动作更快但常失败，也不意味着吞吐更高。

“使用在线采集数据”不等于“每一步都在线更新权重”。 RECAP 的策略执行、数据聚合、价值学习与策略改进可以交替进行，其论文强调通过迭代的离线学习过程利用收集到的经验。它也不是对每个新任务完全不需要人的纠正或结果标注。π*0.6 论文 §IV–V

12. π0.7：用更丰富的条件组织更多、更复杂的数据

12.1 核心变化是把“怎么做”也放入条件

2026 年 4 月发布的 π0.7 强调 steerability（可引导性）与 compositional generalization（组合泛化）。如果训练数据里既有快慢不同的操作、不同控制模式，又有成功与失败，只有“折衣服”三个字往往不足以解释这些行为差异。

π0.7 因此扩展模型的条件：除了任务文字，还使用更细的子任务、视觉子目标、episode 元数据和控制模式。它继承 π0.6-MEM 的架构方向：约 4B 的 Gemma 3 VLM、约 860M 的连续动作专家及视觉历史编码，论文称总规模约 5B。π0.7 技术报告 §IV、VI

这里的约 5B 描述策略模型的规模，不能直接当成包含独立子目标生成模型、高层策略在内的整套系统参数量或显存需求。部署预算还要计入这些模块、视觉上下文缓存和动作采样时的中间激活。

子任务与控制模式并非到 π0.7 才首次出现：π0.5 已使用高层子任务，并通过文字区分关节／末端动作。π0.7 的重点是把更细的语言、视觉目标、历史和行为质量条件组合起来，让更异构的数据可用于同一个策略。π0.5 §IV-C

这不是只在现成模型的 prompt 里添加几个形容词。模型在训练时就要看到对应字段及其行为差异，部署时这些条件才有可能成为有效的控制接口。

12.2 模型每一步可以额外看到什么

对杯子任务，“放到托盘上”可能仍不够明确：靠左还是靠右，杯柄朝哪边，是否已经拿起过杯子？不同条件分别补充不同信息。目标图像可以指定希望出现的布局，历史帮助判断刚才发生了什么，质量与速度标签则表达期望的行为风格。它们一起约束“应该生成怎样的动作”，并不直接替代动作生成。

例如，两段示范最后都把杯子放对了，其中一段中途反复调整、耗时更长。若训练只提供相同的任务文字，两种行为都会成为该条件下的样本；补充行为元数据后，模型才有机会学习哪些差异对应“更流畅”或“更快”的条件。部署时选择条件，是在调用已经学到的这种关系，不能靠添加训练中从未使用过的字段获得同样效果。

12.3 记忆不是简单地把所有旧图片塞进上下文

π0.7 使用 MEM 风格的视觉历史编码器，对历史图像进行时空压缩，使历史不必按原始帧数线性占用同样多的视觉 token。相关 MEM 工作还区分短期视觉历史与长期语义记忆，分别服务于运动状态理解和长程任务进度。MEM 方法说明

在 π0.7 报告的设置中，最多接入四路当前相机，每路最多六帧历史，历史采样间隔为 1 秒；观测图像与子目标图像缩放到 448 × 448。历史本体状态也进入主干，每个状态经线性投影成为一个位置。训练会随机丢弃历史；对应的状态位置同时被 mask，保持图像历史与状态历史的可见性一致。π0.7 §VI-B

因此，描述一个 VLA 的输入时，除了“几路摄像头”，还要问：是否读取历史、历史间隔多大、怎样压缩、是否保存已完成子任务。单张图像里看不出杯子刚刚被拿走还是一直不存在，也可能看不出衣物哪一步已经做过。

例如，夹爪都出现在杯口附近的一张画面，可能来自“正在接近”或“刚刚离开”的不同过程；接触部位又可能被遮挡。连续几帧提供运动方向和近期事件，能减少只凭当前外观产生的歧义。这里的关键是历史改变了可获得的信息，而不是把同一张图片重复输入几次。历史仍可能丢失细节，也不能替代新的传感器反馈。

12.4 世界模型生成的是子目标，不是提前拿到真实未来

π0.7 的子目标图像可以由一个基于 BAGEL 的图像生成模型产生：根据当前场景、子任务与条件，给出接下来希望达到的视觉状态。VLA 再利用这个图像引导动作。它们是不同职责：世界模型提供视觉目标，动作策略产生具体控制量。

回到杯子任务，文字“放到托盘上”允许很多具体摆法。一个目标图可以进一步展示杯子位于托盘内部偏左的区域。策略同时看到“现在杯子在外面”和“希望出现这种摆法”，据此选择运动；目标图本身没有给出机械臂应该经过哪些关节位置。

训练中可以从示范轨迹的未来帧构造目标图像，也会使用生成的子目标，减轻训练时真实图像与部署时生成图像之间的差异。论文并非要求每个样本始终带目标图：会对子目标和部分提示字段做采样或 dropout，使模型适应条件缺失。π0.7 技术报告 §V-B、VI-C

这里还有两层不同的采样比例：论文只为每个 batch 中约 25% 的样本加入视觉子目标；在使用真实未来图像构造子目标时，又以 25% 概率取子任务片段末帧，其余从未来 0～4 秒内采样。前者决定多少样本带这种条件，后者决定条件对应多远的未来，不能把两个 25% 混成同一个概率。π0.7 §V-E、VI-C

并非所有非机器人数据都要补出关节动作。报告中的网页问答、定位、文本与视频描述提供各自的监督；分段标注的人类视频还能用于子目标生成模型训练。图像中的人体运动并不天然等于某台机械臂的可执行控制量。π0.7 §VI-A、附录 C

部署时不能把评估轨迹的真实未来帧偷拿来当条件。生成图像也不是物理仿真保证：一张看起来合理的折好衣服图片，不保证当前夹爪、遮挡与接触状态存在可行路径。

12.5 质量、速度与失败轨迹怎样共存

原论文中的元数据包括 episode 长度所表示的速度、1～5 级整体质量，以及动作片段是否发生错误。训练时根据记录和标注提供这些条件；推理时可以请求高质量、无错误等期望条件。

这与“看到失败数据就模仿失败”不同：模型学习的是带上下文的行为分布。它还可以吸收 π*0.6 等专用策略产生的自主经验，把部分专家行为汇入同一个通用模型。请求 quality=5 只是一个学到的条件，不是成功保证；这种条件训练也不应直接等同于每一步在线 RL。π0.7 项目说明

12.6 可组合技能，不等于完全没有相关训练经验

官方展示包含把已有技能迁移到新的“机器人—任务”组合，例如用没有采集过该任务示范的双臂 UR5e 折衣服。应把它读成目标具身与任务组合未见，而不是“训练从未出现衣物折叠，也从未出现这台机器人”。

空气炸锅例子也需要分层描述：一句零样本总指令、逐步语言指导、再根据指导数据适配高层策略，其自主程度不同。作者还明确讨论过训练集中相关设备交互的例子，因此不能把“未采集这个完整任务”扩写成“模型从未见过空气炸锅”。π0.7 组合任务与跨具身实验

判断这种泛化能力，最好拆成四个独立问题：是否见过物体、是否见过环境、是否见过技能、是否见过当前具身与技能的组合。一个“zero-shot”标签无法同时回答它们。

12.7 动作块路线仍在，但实时执行更明确

π0.7 继续输出 50 步连续动作块。论文报告其评估使用 5 次采样更新，并采用训练时 RTC 来处理异步推理；不同实验执行 15 或 25 步前缀。这里 5 次采样、50 步预测、15／25 步执行仍然是不同数量。π0.7 §VI–VII

丰富的提示、视觉子目标和历史会改变计算开销，因此需要分开测量高层语言、目标图生成、VLA 动作生成与机器人执行。论文采用异步线程更新部分条件，不能根据一段视频反推出所有模块共享同一频率。

附录给出了更具体的成本边界：最小 π0.7 配置在 H100、三路相机与五次采样下约需 38 ms；加上视觉历史和子目标上下文，报告最重配置可到约 127 ms。这两项都描述 VLA 推理，不包括重新生成一组视觉子目标。

独立子目标模型基于约 14B 的 BAGEL。论文使用四张 H100 的张量并行、8-bit 大矩阵运算等优化，以 25 次采样约在 1.25 秒内生成子目标；系统在子任务变化或距离上次生成达到约 4 秒时异步更新。因而，动作生成与视觉目标更新必须有不同的时间安排。这是报告中的系统配置，不是 π0.7 所有部署都必须照抄的硬件清单。π0.7 §VII、附录 C–D

12.8 两个消融，分别看数据数量与数据多样性

π0.7 不只展示最终机器人视频，也在衣物折叠实验中把数据按质量与速度分成“最好 30%、50%、80%、全部”四档；每档各训练带元数据与不带元数据的模型，共八个模型。报告中，不带元数据的版本在引入更多低质量数据后可能退化，带元数据的版本则能继续受益。它验证的是条件设计与数据组成的交互，不能简写为“失败数据越多越好”。

另一个消融比较“去掉任务多样性最高的 20% 数据”和“随机去掉 20% 数据”。两者去除量相同，用来区分数据数量与被去除内容的影响；报告中前者在所测短程未见任务上退化更多。这个设计适合迁移到自己的数据研究：删掉一类数据时，增加同数量的随机删除对照，才能更清楚地解释来源价值。π0.7 §IX-E、Fig. 18

这些都是该论文的实验结论；混合失败数据之前，仍需有稳定的标注口径、训练条件和独立评估，不能只把旧日志不加区分地放进模仿学习。

历史或 RTC 是否有用去掉历史／去掉对应实时机制控制周期、延迟注入、动作块长度遮挡、动作衔接、闭环反应

比较不同输出头时，训练 FLOPs 相同、GPU 小时相同和更新步数相同，通常不能同时做到。应明确采用哪一种预算，再同时报告另一种成本；不要悄悄把更多训练资源算成架构优势。

去掉预训练的对照也不一定公平地只改变了“有没有知识”：若参数规模、初始化、优化难度或训练步数同时不同，结论需要缩小到实际实验所支持的范围。

14.3 把“泛化”写成可检查的划分

建议至少分开记录：

  • 对象与场景：测试物体实例、家庭、背景是否进入过训练。
  • 任务与策略：新指令措辞、新技能组合，还是全新运动技能。
  • 具身：机器人本身没见过，还是只没见过该机器人执行这个任务。
  • 辅助条件：是否有人逐步指导、是否使用目标图、目标图由谁提供。
  • 独立试验：重置方式、试验次数、随机种子、成功判定、超时和人工接管规则。

相邻视频帧不是独立试验，同一条 episode 的滑动窗口也不是独立测试任务。对跨家庭泛化，按帧随机分割很容易让同一个房间同时进入训练和测试；应按能表达研究问题的实体分组划分。

如果报告每小时成功数，计时还应说明是否包含重试、失败恢复、人工接管与场景重置。只有成功视频的平均完成时间，不等于部署期间的真实吞吐。更系统的指标口径可参考训练与评估指标专题。

14.4 Flow loss、采样质量和闭环成功率怎样一起读

比较两个 Flow Matching checkpoint 时，先保证验证条件一致：同一批 episode、同一动作归一化、相同有效维度与时间采样分布。否则 loss 的变化可能来自计分方式。还可以按低、中、高噪声时间段分别统计，检查平均值是否掩盖了某一段拟合变差；各段最后怎样加权，也要保持一致。

指标直接测到什么需要一起记录
条件速度监督 MSE对抽样路径速度标签的平均拟合误差时间分布、动作尺度、有效位置、聚合规则
生成动作的离线误差样本与一条记录动作的距离初始噪声、采样数、动作坐标与物理单位
分布与模式检查是否保留多种行为、是否落入低密度中间区目标分布是否已知、指标是否适用；小实验的 W1W_1W1​ 不直接推广到真机
闭环任务与时延动作经过执行与反馈后能否完成任务相同初始场景、控制周期、超时、人工介入与 P95 延迟

Flow loss 不是直接报告样本的负对数似然，也不是成功概率。 第 6.11 节里精确场仍有非零监督 MSE，说明不存在一个与所有数据和归一化通用的“低于某值便会成功”的阈值。多峰任务中，一条与记录不同但可执行的动作，也可能得到较大的点对点误差。

比较积分器时，可以固定 checkpoint、观测和初始噪声，逐项改变 Euler／Heun 与 NFE，先隔离采样算法的作用；再增加独立噪声与匹配场景，观察输出波动和实际控制效果。第 6.11 节的固定分位点正是为了减少随机初值对求解器比较的干扰。真机每轮执行会改变后续状态，所以离线共用噪声不能替代重复的闭环试验。

如果一次生成十条轨迹，再用测试真值挑出误差最小的一条，应明确报告 best-of-10 和选择器使用了什么信息。它与部署时只能执行一个样本的表现不同。若用额外评分器选择，就要把评分器误差、耗时和数据来源算入完整系统。

更长的积分不一定值得：在静态桌面上改善的动作精度，可能被动态任务中新增的观测陈旧时间抵消。因此，选择 NFE 时同时画“质量—耗时”关系，比单独追求最低离线 loss 更接近实际部署问题。

阅读自测与验收

  • 七维末端动作是否表示七个关节或七个时间步？ 都不一定；常见接口是三维平移、三维旋转和一维夹爪，共同描述同一个控制步。
  • 一次示范截成 951 个窗口，是否得到 951 次独立任务试验？ 没有；它们来自同一条 episode，相邻窗口通常高度重叠。
  • Flow Matching 的初始噪声会先发送给机器人吗？ 不会；它是计算机中的生成起点，完成采样与动作转换后才交给执行接口。
  • 模型推理用了 73 ms，最后一行动作的观测年龄也只有 73 ms 吗？ 不是；执行前缀期间时间继续流逝，必须从采集时刻算到实际使用时刻。
  • RT-2 输出的是自然语言运动说明吗？ 主要动作路径输出可解码为数值控制量的动作 token。
  • OpenVLA 的 7B 对 55B 是否隔离了参数量因素？ 没有；数据、结构、训练与具体任务都要一起看。
  • 为什么不能说动作无法回归？ 确定性回归有表达与损失上的取舍，但在合适数据和任务上可以很有效。
  • π0 的 50 个动作位置与 10 次采样是什么关系？ 每次采样更新整个 50 步动作块。
  • 50 Hz 是否表示每秒运行 50 次完整大模型？ 不是；动作执行频率、块更新频率和内部采样次数不同。
  • π0 的后训练与 π*0.6 的后训练是否相同？ 原始 π0 主要用监督示范，RECAP 进一步使用奖励、价值和自主经验。
  • Flow Matching 的平方误差为什么不必把两种动作平均成零？ 它拟合依赖噪声位置与流时间的向量场，不同初值可以保留不同输出模式。
  • RECAP 的价值数值是否等于成功概率？ 不是；本文讨论的价值由任务回报构造，同时受完成、耗时与失败惩罚影响。
  • KI 是否把 VLM 完全冻结？ 不是；主干仍由离散／文字目标训练，只隔离指定连续分支的梯度。
  • π0.7 的视觉子目标是否是真实未来观测？ 部署时通常是生成的目标条件，不能使用尚未发生的评估真值。
  • 没有目标具身的折衣服数据，是否意味着训练从未出现折衣服？ 不是；这是需要明确任务与具身组合的泛化问题。
  • 技术报告发布是否代表权重已开放？ 不是；应分别检查论文、官方代码、checkpoint 与数据。
  • 训练直线插值是否意味着一步 Euler 足够？ 不是；边际速度场随状态和时间变化，精确场也有积分误差。
  • 8 步 Heun 与 8 步 Euler 的计算预算相同吗？ 不同；本文实现分别需要 16 与 8 次速度场求值。
  • 精确速度场对样本标签的 MSE 必须为零吗？ 不必；条件路径之间的速度差异留下不可约条件方差。
  • 平均阶段进度 77.5% 能写成成功率 77.5% 吗？ 不能；杯子算例的完整成功率只有 60%，应保留各自的分母和判定规则。
  • π0.7 的质量标签就是 RECAP 的优势标签吗？ 不是；前者描述记录或标注的行为属性，后者依赖奖励、价值估计与参考基准。
